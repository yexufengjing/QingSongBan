# 轻松办 · 日历、待办与日记录设计

日期：2026-10-23。本文保留开发前的界面方案、业务规则、交互流程及浏览器交互原型说明；Flutter 正式功能现已接入，当前实现与验证结果以同目录《开发完成说明.md》为准。浏览器原型仍不连接应用数据库。

## 1. UI 设计

### 1.1 定位与入口

日历负责回答“哪一天有什么事、做完了什么、记下了什么”。待办是可完成的计划，日记录是用户主动记录的内容，二者分别展示，不把操作日志或考勤流水自动当作日记录。

正式接入建议：首页「处理」增加「日历与记录」入口，「我的 → 备忘提醒」增加日历视图入口。两处打开同一页面，保留现有首页／考勤／汇总／我的四项主导航；日历作为子页隐藏底部主导航，返回恢复来源页状态。现有首页业务入口不被替换。

### 1.2 手机布局（从上至下）

| 区域 | 内容与作用 |
|---|---|
| 标题栏 | 返回、日历、回到今天；回今天同时切回当前月并选中今天 |
| 月份工具栏 | 上月、2026年10月（可点选年月）、下月；不把年份藏起来 |
| 星期与月历 | 周一至周日，7列；按月份自然排4–6周，补齐首尾相邻月日期并弱化；选中日期切月时保持下文规则 |
| 图例 | 蓝点＝有未完成待办，勾＝当日待办全部完成，短横线＝有日记录；图例持续可见 |
| 当日标题 | 完整年月日、星期、未完成数量；不使用只在今天成立的固定“今日”标题 |
| 待办区 | 未完成在前，显示复选框、标题、时间／全天、必要备注；标题可点编辑，更多菜单含删除；已完成分组默认收起并显示数量 |
| 日记录区 | 多条记录，正文摘要最多3行、创建／更新时间；可展开全文、编辑、删除；独立空态按钮「写一条记录」 |
| 新增入口 | 一个主要「新增」按钮，选择「待办事项」或「日记录」；正文底部预留空间，最后一行不被按钮挡住 |

当日详情是一条自然纵向滚动流，不为待办和记录分别塞入小滚动窗。长列表滚动时可保留紧凑的所选日期标题；月历不强制占满可视区域。平板可让月历与当日详情并排，阅读顺序不变。

### 1.3 日期格与视觉语言

- 今天：描边与“今天”语义；选中：蓝底白字。今天恰好被选中时以选中底色为主，读屏同时说明“今天、已选择”。
- 每格只表达“是否有内容”，不把多条标题或多个彩点挤入月历。待办标记与日记录横线可以共存；无待办不显示完成勾。
- 逾期状态写在当日待办列表中，不把整片历史日期涂红；关闭通知不代表完成，仍属于未完成。
- 延续现有 `AppColors`：主色 `#2563EB`、正文 `#0F172A`、次要文字 `#64748B`、背景 `#F1F8FE`、分隔 `#E2E8F0`，内容白底。完成与错误沿用应用语义色，同时提供勾和文字。
- 标题20sp、正文16sp、辅助14sp；间距8／16／24dp，卡片圆角12dp、输入8dp、弹层16dp。用留白和分隔线组织列表，不叠加装饰性卡片。
- taste 方向：规整、克制、适中密度（variance 2／motion 2／density 5），使用现有中文系统字体和 Material 图标。无渐变、霓虹、虚构统计和持续闪动；动画只帮助理解选择与展开，并尊重减少动态效果设置。

## 2. 功能逻辑

### 2.1 核心对象与日期规则

| 对象 | 建议字段与规则 |
|---|---|
| 待办 | 复用现有 Reminders／ReminderOccurrences。标题去除首尾空格后必填，计划日期必填，时间可选，备注可选；现有分类、优先级、关联对象等在原有完整编辑页维护 |
| 待办实例 | 按 occurrenceId 唯一识别某一次计划；状态 pending／completed，保留 scheduledAt、completedAt，完成不改变计划日 |
| 日记录 | 新增独立 DailyEntries：id、recordDate、content、createdAt、updatedAt、isDeleted；正文非空，一天允许多条，标题可由正文首行摘要生成，无完成状态 |
| 页面状态 | displayedMonth 与 selectedDate 分开保存；初次打开选今天，同一页面返回保留月份、选择和列表位置 |

日期归属使用本地民用日期，不通过 UTC 截断字符串推导。日记录保存 `YYYY-MM-DD` 日期键，创建／修改时间另存时间戳。待办按计划日归属，时间型事项沿用既有时区规则；跨时区保持原计划时区含义，详情显示时区，不能静默改变记录日期。全天待办需显式 `isAllDay` 语义，不能把午夜时间擅自视为全天。

单日查询使用该日零点（含）至次日零点（不含），月份查询同理包含首尾补齐日期。按日历构造次日／下月边界，不能依赖固定24小时或30天。历史未完成仍留在原计划日，显示逾期，不自动移到今天；需要调整时由用户改期。全天待办到次日才逾期，指定时间待办到计划时刻后逾期。

没有日期的已有提醒保留在原备忘列表中，不擅自放入今天；日历提供「无日期事项」入口跳回相应列表。系统提醒设置不是用户待办，不画进日历。已删除事项不计入数量；已跳过重复实例不算未完成，也不冒充已完成。

### 2.2 待办操作

| 操作 | 成功后的状态 | 失败与边界 |
|---|---|---|
| 创建 | 默认所选日期，保存后列表与月历标记同时更新 | 标题空白时字段下提示；写入失败保留表单，不能提示“已保存” |
| 编辑 | 保持同一id；改期后从旧日移出，切到新日并提示“已移至×月×日” | 不改创建时间，不生成副本；提交时禁用重复保存 |
| 删除 | 确认具体对象后软删除，原日数量与标记更新 | 删除待办不删除当天日记录；失败保持对象可见并可重试 |
| 完成／恢复 | 勾选切 completed，记录 completedAt；恢复 pending 并清空 completedAt | 状态提交失败回到原状态；恢复历史事项后可能显示逾期 |

正式接入后「备忘提醒」与「日历」观察同一数据源，状态互通；日历不能另外存一套正式待办。月历摘要和详情由同一已提交数据快照派生。

已有重复提醒按每次实例所在日期出现。完成或恢复只影响所点实例；日历快捷编辑与删除首先覆盖单次事项。重复系列进入既有完整编辑流程，修改系列前明确提示其影响，不默认改全部；删除系列需明确说明会删除整组。若提供“跳过本次”，沿用现有 skipped 状态且与删除区分。原型只演示单次事项，不模拟重复系列。

### 2.3 日记录管理

允许为过去、今天或未来日期写记录，不自动限制成“只能今天写”。默认所选日期，可修改；修改归属日期后跳转到新日。按创建时间倒序排列，编辑不把旧记录伪装成新建；标明更新时间。保存、展开、编辑与删除均不改变当日待办状态。正文空白不能保存，换行保留；空态表示没有内容，加载失败必须显示重试，不能显示成空态。

### 2.4 与现有工程的接入点（尚未实施）

- Flutter／Riverpod／Drift 为现有技术栈；颜色以 `lib/app/theme/app_theme.dart` 为准，主导航以 `lib/app/router/app_shell.dart` 为准。
- 复用 `lib/features/reminders/data/reminder_repository.dart` 和 `application/reminder_providers.dart`，完成动作明确传 occurrenceId。现有 `findItemById` 对重复实例使用 `.single`，日历详情不能直接假设它能查单个重复实例，需要按实例查询入口。
- 现有 `_replaceScheduleData` 为 upcoming 生成有限30个实例。正式月历需按可见日期范围补齐计划实例并依 unique(reminderId, scheduledAt) 去重；必须保证远月与重复结束边界正确，不能把“尚未物化”显示成“没有待办”。
- 新增 DailyEntries 需版本迁移、按日查询索引，纳入现有备份与恢复。全天／指定时间语义也需明确迁移规则；旧数据保持原计划时间，不能全量改成全天。
- 通知沿用已有 NotificationService，日历本身不另建通知调度器。关闭通知不影响待办可见性；完成、删除和改期后同步取消／重排相应通知。
- 现有事项流主要观察 reminders 表，正式接入须确保实例单独变更也触发月历摘要刷新。

## 3. 交互设计

| 场景 | 用户操作 → 界面响应与反馈 |
|---|---|
| 进入 | 选择今天，加载该月与当日数据；加载错误显示重试，实际空数据分别展示待办和记录空态 |
| 切日期 | 点击日期格 → 立即更新选中样式和下方完整日期，展示当日两个分区；点击灰色相邻月日期同时切月 |
| 切月份 | 左右滑月历或点箭头 → 切至上／下月；保留选中的“日”，不足则取月末，如1月31日→2月28日；下一次以实际选中日为准 |
| 远距离跳转 | 点击年月 → 年月选择；确认后按同一月末规则选日；取消不改变页面；回到今天一键恢复 |
| 新建待办 | 点新增→待办事项→标题、所选日期、可选时间与备注→保存；保存成功关表单、更新摘要与列表，焦点回列表相关项 |
| 新建记录 | 点新增→日记录（或空态写记录）→正文与日期→保存；成功后出现在当日记录首部 |
| 完成／恢复 | 点复选框→提交并显示行内进行态→成功移入／移出已完成组；Snackbar提供状态文字，失败恢复并保留重试入口 |
| 编辑 | 点击待办标题或记录编辑→加载原内容→保存；日期未变则留原日，改期则跳到新日；成功后显示“已更新” |
| 删除 | 更多→删除→确认框展示对象摘要及日期→删除；成功更新列表，失败不关掉有用上下文 |
| 展开记录 | 点展开全文→原位显示内容；收起返回摘要；不额外打开全屏只读页 |
| 退出编辑 | 内容未改直接关闭；已改则选择继续编辑／放弃更改，不因误点遮罩丢失输入；保存失败输入继续保留 |

长表单正式使用独立页，短新增可用底部弹层；键盘升起时表单可滚动、保存可到达。日期格有完整语义，如“2026年10月23日，今天，已选择，2项未完成，1条记录”，不能让读屏只读出“23”。复选框与编辑区域各自可点，点击完成不误开编辑。

## 4. 关键点与验收边界

1. **同一事项只有一份正式数据**：日历是备忘提醒的日期入口，日记录单独保存；不修改考勤、工资等业务记录。
2. **计划日与完成日分开**：补做昨天事项，仍归昨天；跨年、闰年、月底、全天与时区均要按日期语义验证。
3. **高密度靠摘要解决**：月历格只给稳定标记，完整数量与内容在详情中读；不用颜色作为唯一信号。
4. **可达性优先**：Android按钮／行命中高至少48dp；窄屏7列格宽可能不足48dp，不重叠扩展命中区，需评估紧凑月历与等价日期列表。大字体换行不裁字，支持读屏和减少动态效果。
5. **保存反馈真实**：写入成功才报成功，失败保留输入，删除确认对象，避免双击产生副本。
6. **首版范围**：日期浏览、单次待办CRUD与完成恢复、多条文字日记录；不增加协作、附件、农历、跨日排程或新的重复规则。已有重复提醒按现有能力接入，需补齐范围查询。

交互原型：`calendar-prototype.html`，本地浏览器专用存储，初始为空；只有点击「载入演示数据」才生成明确标识的示例。原型用于评审布局和流程，不证明数据库迁移、通知、备份或真机可用。正式接入后重点验证：旧提醒兼容、两入口状态同步、月底切换、重复实例、失败恢复、通知重排和备份恢复，再进行实体Android设备与大字体检查。

### 本轮检查结果

- GPT-6-luna 高推理子代理编写原型，主 Agent 审查并要求修正类型选择、月底选日、存储失败回滚和窄屏布局等具体问题；仅使用一个子代理。
- 主 Agent 独立复跑内嵌 JavaScript 的 `node --check`，退出码0。子代理对原型实际日期函数做断言，覆盖普通年／闰年1月31日切2月、跨年、3月31日切4月，以及公元1年和99年。
- 浏览器安全策略禁止打开本地 `file://` 页面，未绕过限制；本轮没有浏览器渲染、完整CRUD交互或Android真机验证。上述检查不等于视觉验收。
- 本轮只新增本目录的设计文档、视觉规范与交互原型，没有修改Flutter、数据库或现有业务数据。
