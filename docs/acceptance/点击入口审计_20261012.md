## 路由覆盖和执行证据

`test/app_route_contract_test.dart` 用 `QingSongBanApp` 挂载生产 `appRouter`，对 91 个样本逐项调用 `go` 并核对 `GoRouterState.name`。错误输入另设测试，分别检查无效人员 ID、缺少采购详情 ID、未知路径。合同测试两项均见最终合并日志通过；缺少 ID 的保险变更编辑和提醒编辑按生产行为明确重定向到列表页，不作为未实现路由。

`test/app_route_render_test.dart` 分两遍实际进入生产 Router 页面：第一遍遍历全部 91 个目标，动态 ID 用 `999999` 检查记录缺失态；第二遍遍历 33 条含动态 ID 的路径，用员工、考勤组、假勤、工资、保险变更/参保人、提醒、库存单据、采购请求、车辆和维修单等真实 seed 记录，以及最小园林维修记录，检查真实记录态。每次进入都推进有限帧，检查没有 Flutter 异常/ErrorWidget/持续加载指示，再返回首页确认路由仍可用。数据库是 `AppDatabase.forTesting()` 的内存库。StatefulShell 的分支页面会保留在 offstage 栈中，因此测试验证活动页面离开及返回，不把预期的分支保留误判成泄漏或销毁失败。
