# 智能助手第一批快捷查询验收

日期：2026-10-22。验证设备：Android API 35 模拟器 `emulator-5554`。未使用物理手机进行构建安装或测试。

## 已实现

- 欢迎页提供考勤、工资与依据、低库存物资、待到货采购、福利领取、车辆维修六类可点击入口。查询直接使用本地读取流程，不需要 API Key，不调用模型解析。
- 考勤和工资支持搜索并选择实际人员，按工号区分同名人员；车辆维修支持搜索并选择车辆。当前页面的人员、车辆和月份可预填到条件中。
- 月度查询支持前后月、本月、上月和日期定位月份。车辆维修按报修月份筛选，实际费用按所选记录累计；库存和采购不显示无效的月份条件。
- 收藏保存人员/车辆 ID、业务类型和固定月份，保存在现有 AppSettings 中，不新增数据库表或依赖。支持一键重查和移除；聊天过程中可通过“快捷查询与收藏”继续使用。
- 结果提供适用的月份切换、福利领取状态及采购到货状态按钮。后续查询绑定原结果的查询条件，不从最新一轮聊天继承其他人员或业务域。未入考勤名单的结果仍可切换月份。
- 原有刷新、明细和业务来源入口保留；浮窗内的选择器使用自己的导航层级。

## 工资待核对来源跳转修复（2026-10-22）

实际触发链：已有主界面 → 全屏助手 → 工资查询结果 → 查看工资待核对来源。原先将工资来源再次压入分支导航，会重复创建已有 shell 页，触发 Navigator 的 `!keyReservation.contains(key)` 断言；底层 ErrorWidget 显示为深红色背景。此前直接从 `/assistant` 启动的来源测试未覆盖已有 shell 的场景。

工资首页及子页面改由根 Navigator 承载；原来依赖 AppShell 的工资首页、编辑、历史和设置页面补齐 Scaffold。新增回归测试覆盖真实初始导航栈、工资来源、设置子页面、返回对话、再次打开来源。

修复后：助手及普通导航回归 148 项通过；来源跳转、路由契约和缺失/真实记录渲染检查通过；两个改动 Dart 文件静态分析无问题；普通调试 APK 构建并安装到 `emulator-5554`。模拟器实际点击该来源两次均正常，返回后原对话保留。证据位于 `build/assistant-source-navigation-fix/`，包括修复前后截图、返回助手截图及日志。未操作物理手机。
