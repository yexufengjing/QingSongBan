## 1. 文档效力与已确认决策

基础文档保留长期方向；首期的具体范围以本文为准。本文不授权扩展业务功能、改变既有统计规则或改动现有业务数据。后文的类型、适配器和接口名称为拟定契约，不代表代码中已存在。

| 项目 | 首期决定 |
|---|---|
| 用户 | 开发者本人自用，不新增多人角色与权限系统 |
| 价值 | 通过自然语言减少跨页面查找、筛选和汇总操作 |
| 场景 | 个人月度考勤；单车年度维修费用；全部车辆年度维修费用排名 |
| 操作范围 | 查询、汇总、本地展开明细和跳转原页面；不生成业务草稿，不新增、修改或删除业务记录 |
| 模型 | DeepSeek，用户自己的 API Key；保留 Provider 替换接口，首期不接第二模型、不自动切换 |
| 数据外发 | 默认仅外发第 3 章白名单汇总；明细按单次请求确认具体字段和范围 |
| 入口 | 全局入口、App 内全局悬浮窗、相关考勤与车辆页面的“问助手”；不新增底部 Tab |
| 上下文 | 当前明确输入优先；继承本轮已明确对象/时间，其次当前页面对象；仍不明确则询问，同名对象提供选择 |
| 历史 | 本机保存，可继续与删除；历史结果带查询时间，再次查询重新读取业务数据 |
| 失败 | 保留问题和已取得的本地结果，提供重试及原页面入口 |
| 验收 | 结果准确、任务稳定完成，并比现有页面操作更省时 |

现有底部导航以当前代码为准，不沿用基础文档中固定“五个”的描述。当前 `AppShell` 展示首页、考勤、报表、设置四个入口。

## 2. 全局悬浮窗范围与生命周期

### 2.1 覆盖边界

已确认：仅在 QingSongBan App 内跨页面显示，支持展开、收起和拖动；离开 App 后不显示，不申请 Android 系统悬浮窗权限，不增加前台常驻服务或跨 App 读取能力。

全局入口保留为普通页面可触达的入口；悬浮窗作为可隐藏的快捷入口。两者以及页面“问助手”使用同一会话状态，不创建互不相通的助手实例。

### 2.2 状态与动作

| 状态 | 表现与转换 |
|---|---|
| 隐藏 | 不占用页面；可由全局入口重新打开，关闭悬浮窗不等于删除历史 |
| 收起 | 仅显示可拖动入口；点击展开，拖动结束停留于安全区域内 |
| 展开 | 显示当前会话、查询条件、输入区和结果；支持收起、关闭、打开独立助手页 |
| 查询中 | 可收起；收起不自动重复发起请求。取消动作使当前请求失效，迟到响应不得覆盖新任务 |
| App 后台 | 不显示悬浮内容，不启动新的模型请求；对已发出的请求可尝试取消，已完成的本地结果保留，返回后不自动重新收费调用 |

交互设计按以下要求细化，不再引入新业务能力：

- 悬浮层位于全局路由之上，覆盖 shell 内和 shell 外的 App 页面；只挂到 `AppShell` 无法覆盖全部车辆独立路由。
- 位置限定在屏幕安全区，避开状态栏、底部导航、键盘及主要保存/新增按钮；键盘弹出、旋转或窗口尺寸变化后重新约束位置。
- 返回键先关闭局部选择/授权弹层，再收起展开的助手，再交给原页面处理；同一次返回只处理一层。
- App 原有对话框、选择器、系统授权和文件选择流程优先；助手暂时收起或隐藏，不遮挡操作，不截获其结果。
- 独立助手页打开时不重复显示第二个悬浮入口；退出后恢复单一入口。
- 跨页面移动不改变正在执行的任务对象。页面上下文更新为“可用于下一次查询”，已有会话对象仍按第 5 章规则处理。
- 悬浮位置可以仅在当前运行期间保留；位置持久化、动画和具体尺寸由交互设计确定，不作为首期业务验收的额外功能。

## 3. 数据外发字段契约

### 3.1 数据通路

```text
用户问题 → 意图解析 → 本地实体解析/选择 → 只读业务查询
                                             ├→ LocalResult → 本地卡片/明细/来源页面
                                             └→ OutboundProjection → DeepSeek 解释
```

`LocalResult` 与 `OutboundProjection` 必须是不同类型。禁止直接序列化数据库实体、整个 ToolResult 或本地卡片对象作为模型请求。所有模型请求，包括解释、追问、重试和历史摘要，都经过同一白名单投影。

### 3.2 默认允许外发

以下为“可按任务需要发送”的上限，不要求每次发送全部字段。字段单位与规则版本随结果附带，防止模型误读。

| 类别 | 允许字段 | 约束 |
|---|---|---|
| 用户输入 | 本次用户主动提交的问题文本 | 用户已知输入框中的姓名、车牌等会随文本发给 DeepSeek；App 不自动从数据库补齐身份信息 |
| 非业务控制信息 | Tool 名称与参数 Schema、语言、单位、结果状态、口径版本；相对日期解析所需的本地日期/时区 | 不含文件路径、设备标识、API Key、数据库信息和原始异常 |
| 临时引用 | `entityRef`、`resultRef`、排名 `alias` | 随机会话引用或当前结果匿名代号，不使用数据库 ID、人员编号、车牌或其可反推编码；绑定会话并在本地校验 |
| 考勤汇总 | `yearMonth`、`attendanceDays`、`leaveAndRestDays`、`overtimeMinutes` | 只针对当前已选人员；不自动发送逐日记录或人员/考勤组名称 |
| 单车维修汇总 | `year`、`completedRepairCount`、`actualAmountCents`、`currency=CNY` | 使用第 4.2 节固定口径；不发送车牌、车辆名称、维修单号 |
| 车辆排名 | `year`、每行 `alias/rank/completedRepairCount/actualAmountCents` | 匿名代号仅在当前结果集内稳定；不传真实车辆身份 |
| 排名覆盖信息 | `totalVehicleCount`、`returnedCount`、`hasMore`、`nextCursor` | 游标为会话绑定的不透明引用，说明分页覆盖范围；不能把当前页描述为全部车辆 |

姓名和车牌只在本地卡片恢复显示。模型文字继续使用“该人员”“当前车辆”或匿名代号；不得对整段生成文本做简单字符串替换来恢复身份。

### 3.3 默认禁止自动外发

| 数据 | 本地用途 | 外发规则 |
|---|---|---|
| 姓名、人员编号、班组/区域/考勤组名称、车辆名称/编号/车牌、数据库内部 ID | 实体选择、卡片标题、导航 | 不自动发送；明细授权仍以匿名代号为主，内部 ID 始终不发送 |
| 每日考勤、单条加班、逐张维修单/费用明细 | 本地展开、核对来源 | 仅可按第 3.4 节单次确认后发送明确子集 |
| 备注、工作内容、故障描述、维修负责人/厂商、附件和文件内容 | 原业务页面查看 | 首期不纳入外发字段，即使包含在数据库查询对象中也必须剔除 |
| 身份证、手机号、银行卡、地址、工资、保险、API Key | 原业务或安全存储 | 首期业务结果外发一律禁止；API Key 仅用于对 DeepSeek 请求鉴权，不进入消息、日志或 Tool 参数 |
| 全部人员/车辆候选清单、整个数据库、完整本地历史 | 本地业务/会话存储 | 不整体发送；实体候选在本地选择，历史按第 9 章重建最小模型上下文 |

用户主动输入文本与 App 自动附加数据库数据分别处理：本契约不声称能识别或自动脱敏用户输入中的全部敏感内容。首次配置及输入区说明文本会被发送；不主动附加未获允许的业务内容。

### 3.4 明细外发的单次授权

本地“展开明细”不触发模型请求，也不弹外发确认。只有用户要求模型解释逐条明细时，才进入发送确认。

授权面板明确展示：接收方 DeepSeek、对象的本地标签、时间范围、字段列表、记录数量和实际待发送内容预览；提供“仅本地查看”和“本次发送”。同一时刻只确认一个明确请求。

首期可申请的明细字段限于：

- 考勤：日期、上午/下午状态；加班：日期、时长分钟。不含备注、地点、登记人及具体工作内容。
- 维修：报修日期、完成日期（可空）、状态、实际金额；若确需费用项目，限数量、计数单位、单价和小计，项目用匿名序号，不发送自由文本。
- 对象仍使用匿名引用，不默认外发姓名和车牌。上述范围以外的数据不因“已确认”而自动解禁。

授权绑定当前请求、结果快照、Provider、对象、时间、字段和记录范围。更换对象/字段、增加记录、刷新数据或重试发送均重新确认；用户取消不得发送。授权结果只记录在本机，不变成长期许可；已授权明细不自动进入后续模型历史。

## 4. 场景与确定性业务口径

### 4.1 S1：个人月度考勤

**问题示例：**“查王某 2026 年 9 月考勤”“那李某呢？”示例仅描述输入方式，不代表真实人员或业务数据。

输入为本地确定的人员与解析完成的 `yearMonth`；考勤组由页面上下文或该月有效名单推导。人员按内部 ID 在本地确定，同名且上下文不能唯一确定时才在对话中追问。考勤组不作为固定用户输入步骤：多个有效组若对应同一人员、同一月份的相同考勤记录与规则，适配器验证汇总一致后返回一次个人汇总，附本地来源组信息；只有组差异会影响结果且无法从上下文确定时才追问。不能直接使用人员当前默认组替代历史月份所属组。

默认卡片展示：本地人员标签、年月、考勤组、出勤天数、请假与休息合计、加班总时长、统计口径、查询时间；提供本地每日明细、加班明细、刷新和原页面入口。

确定性来源：

1. 复用 `MonthlyAttendanceTableRepository.watchTable(yearMonth, groupId)` 的有效名单、未删除人员/考勤记录和行对象规则；在本地选出目标人员，不把整组数据外发。
2. 出勤天数使用 `MonthlyAttendanceTableRow.attendanceDays`；上午/下午出勤各计 0.5 天，沿用其离职处理逻辑。
3. `MonthlyAttendanceTableRow.leaveDays` 实际包含 `leave` 与 `rest`，在助手中明确命名为 `leaveAndRestDays`，标签必须是“请假与休息合计”，不得解释成纯请假天数。
4. 加班按 `OvertimeRepository.watchOvertime(month)` 中该人员未删除记录的 `durationMinutes` 求和，不由模型推算。展示小时/分钟时仅做确定性单位转换。
5. 每日显示复用 `cellForDay()`，区分未登记、未入职、离职等状态。未登记不等于缺勤；无记录不等于全月正常。
6. 同一人员多组时不能把相同按人记录重复汇总。按当前明确组查询，或在多组的人员月度记录/规则/结果一致时返回一次汇总；不把各组结果相加。若无法验证一致则简短追问。加班是人员整月统计，不按组再次拆分或重复累计。

已发现的代码差异：报表 `MonthlySummaryRepository.generate()` 将请假与休息分别统计，且会写入汇总表；其存量汇总可能不代表实时原始记录。首期助手不调用 `generate()` 或状态变更方法，也不静默混用两套口径。若未来要求“纯请假天数”，需另定明确口径并完成相应验证。

状态处理：人员存在但不在该月有效名单，返回 `NOT_IN_ROSTER` 并解释无法按月考勤表统计；在名单但无登记则显示未登记明细及“当前已登记结果”，不能输出“当月无缺勤/考勤完整”。记录存在异常时不擅自纠正既有业务数据；完整性未经现有规则验证时标记 `completeness=notEvaluated`，不将其编码为事实性“完整”。

### 4.2 S2：单车年度维修费用

输入为已选车辆和明确自然年。默认沿用 `VehicleExpenseRepository.list(vehicleId, year)` 的维修费用分项口径：

- 范围：未删除维修单，且状态为 `completed`。
- 年份归属：按 `reportDate.year`，即报修年份，不按完成、支付或结算年份。
- 金额：`actualAmountCents`，以整数分求和；币种人民币。不混入申报金额、保养、油耗、其他费用或另加备件费用。
- 次数：同一集合中的已完成维修单数，字段名为 `completedRepairCount`；不称为包含未完成维修的“全部维修次数”。
- 日期：费用项显示日期可能为 `completedAt ?? reportDate`，筛选年份仍按报修时间。卡片明确显示“按报修年份统计已完成维修单实际金额”。
- 不以是否已支付、已结算作为默认过滤条件；用户另问支付/结算口径时说明首期不支持该口径，提供原页面入口。

卡片展示车辆本地标签、年份、已完成维修单数、实际维修费用、口径及查询时间；本地可展开对应维修单并打开详情。零金额维修单仍计次数；没有满足条件的维修单时显示“该口径下暂无已完成维修单”，不推断车辆从未维修或状态良好。

现有费用分析页中的维修次数可能使用全部报修单计数，与上述“已完成维修单数”不同；助手明确标签，不改原页面，也不把两个不同口径数值当作同一指标进行验收。

### 4.3 S3：全部车辆年度维修费用排名

输入为明确自然年；车辆集合使用 `VehicleRepository.watchVehicles()` 默认未删除集合，包含未删除的停用等状态车辆，不偷偷按状态缩小范围。单车聚合完全复用 S2 规则。

- 在本地对完整车辆集合聚合后排名，不能先截取车辆再排名；关联已删除车辆的维修单不混入集合。
- 按实际金额降序；同金额并列排名采用 `1, 1, 3`，同金额显示顺序按车辆编号、内部 ID 稳定排序；这些身份字段仅用于本地排序。
- 首屏建议每页 10 辆，本地可继续加载；首屏不是全部排名。总车辆数、当前已返回数、分页状态随卡片展示。
- 无符合条件维修单的车辆显示“无该口径记录”，金额按零参与展示；与“有零金额维修单”用单数区分。所有车辆均无记录时不输出“维修最高的车辆”，改为说明无可比较维修记录。
- 点击排名项进入该车辆同年份本地汇总，保留当前排名以便返回。模型只获得当前任务需要的匿名排名行。

## 5. 上下文、实体与时间规则

优先级按字段分别解析：本次明确输入 > 本轮已确认条件 > 相关页面提供的有效条件 > 已定义默认值 > 必要追问。不能因当前页面有车辆就覆盖用户本次输入的另一辆车；“全部车辆”明确清除单车限制。主线为提交一句话后直接得到答案；不展示固定条件表单或确认页。

- “今年/去年/本月”按设备当前本地时区和提交时日期由 App 解析，并展示实际年份/年月；不依赖模型的当前日期。月份存为 `YYYY-MM`，年份为四位自然年。
- “9 月”缺少年份时优先沿用本轮/页面年份；没有则按设备当前年份查询，并在答案中明确显示实际年月与“按今年查询”的简短说明。支持用户直接说“查去年”修正，无需先确认年份。
- “查去年”作为上一查询的时间纠正时，替换为设备当前年份的上一年，保留其他适用条件；绝不能用上一个结果年份再减一而把“去年”误解为逐次向前一年。
- “那李某呢”继承前一条已确认查询的类型和年月，仅重新解析人员；跨场景切换只继承仍适用字段，月份不能被无提示转换为车辆年份。
- 页面提供对象 ID、模块和当前筛选条件，但数据库身份字段不自动外发。不同对象之间有冲突且用户未说明时，展示当前会话条件并让用户选择是否切换。
- 实体搜索先本地匹配，优先使用当前请求/上下文中已明确的对象；无法唯一确定时，在当前对话给出简短候选，点击即完成选择并继续原查询，不增加“继续”确认。零项返回未找到。候选姓名/编号/班组/车牌只显示在本机。
- `entityRef` 仅能由本地解析/选择产生，绑定类型、会话和本地对象；模型伪造、跨类型或跨会话引用必须拒绝。刷新后对象删除则返回失效，不从历史恢复为有效对象。
- 第一版仅支持单月/单年；跨年范围、预测、工资计算等超范围请求给出能力说明和相关原页面入口，不生成伪结果。

## 6. Tool 目录与公共协议

### 6.1 能力目录

| 名称（拟定） | 调用方 | 用途 | 副作用 |
|---|---|---|---|
| `resolveBusinessEntity` | Orchestrator / 模型请求 | 人员或车辆本地解析、候选选择、生成临时引用 | 只读业务数据；可更新会话选择状态 |
| `getEmployeeMonthlyAttendance` | Orchestrator / 模型请求 | S1 人员月度汇总 | 业务只读 |
| `getVehicleAnnualRepairSummary` | Orchestrator / 模型请求 | S2 单车年度汇总 | 业务只读 |
| `getAnnualVehicleRepairRanking` | Orchestrator / 模型请求 | S3 完整集合聚合及分页排名 | 业务只读 |
| `getLocalResultDetails` | 用户点击、本地 UI | 展开当前结果的每日考勤/加班/维修单明细 | 业务只读，不自动调用模型 |

导航、刷新、明细外发确认是受控的本地动作，不注册通用路由、HTTP、SQL、文件或业务写入 Tool。模型能请求的 Tool 使用显式白名单，不能通过任意方法名反射调用 Repository。

### 6.2 公共类型与校验

```text
ToolRequest
  requestId: 本地生成的请求标识
  toolName: 已注册能力名
  arguments: 与该 Tool Schema 一致的参数

LocalToolResult<T>
  status: ok | empty | selectionRequired | error
  resultRef: 本地生成的会话结果引用
  query: 本地已解析对象、年月、筛选条件
  data: T（完整本地结果，不可直接外发）
  sourceRuleId: 固定口径版本
  queriedAt: 本地查询时间
  coverage: 当前页/完整集合及分页信息
  completeness: notEvaluated | partial | complete（只有通过明确规则才可为 complete）
  warnings: 本地受控提示
  error: 可空的受控错误码与可重试标志

OutboundProjection
  只允许第 3 章字段；由本地构造，不接受模型指定要序列化的任意字段路径
```

参数校验：拒绝未知字段/Tool、错误类型和无效日期；`yearMonth` 必须严格规范化为有效 `YYYY-MM`，`year` 为有效四位整数年份；不因输入无效而回落到当前日期。临时引用必须通过本地绑定校验。模型 Schema 校验不能替代 App 校验。

分页建议默认 10、最大 50；本地明细单页最大 50。游标只适用于同一结果集/条件，刷新使旧游标失效。单次聚合基于一致快照；不能把不同查询时点的列表拼成同一排名。上述页大小为设计默认值，可在交互设计中调整，不改变业务语义。

### 6.3 受控错误

| 错误码 | 含义与界面处理 |
|---|---|
| `INVALID_ARGUMENT` | 条件无效；指出需修正字段，不返回业务结果 |
| `MISSING_CONTEXT` | 缺对象/时间；用单个问题补齐当前必要条件 |
| `ENTITY_NOT_FOUND` / `ENTITY_UNAVAILABLE` | 找不到或已删除对象；允许重新选择 |
| `SELECTION_REQUIRED` | 多个同名对象/考勤组；本地选项，不自动猜选 |
| `NOT_IN_ROSTER` | 该人员不在指定月份有效名单；不按零出勤成功返回 |
| `STALE_RESULT` | 结果引用/游标失效；提示刷新后继续 |
| `UNSUPPORTED_SCOPE` | 首期不支持的场景或统计口径；说明范围并给原页面入口 |
| `LOCAL_QUERY_FAILED` | 本地查询失败；显示受控提示与重试，不把失败当空数据 |
| `PROVIDER_FAILED` | 模型连接、鉴权、超时或格式失败；不撤销已成功的本地卡片 |

空结果是成功查询后的独立状态，不能用 `0` 或空数组掩盖任一错误。

## 7. 各 Tool 输入输出契约

### 7.1 `resolveBusinessEntity`

- 输入：`entityType=employee|vehicle`、用户输入 `query`；可使用本地页面对象/既有选择作为本地上下文。缺少搜索词且无对象时询问，不拉取全量数据给模型。
- 本地输出：匹配状态、候选本地标签、可翻页信息；选定后输出 `entityRef`。候选选择暂停下游查询，不能带着未确定对象继续调用业务 Tool。
- 模型投影：`selectionRequired` 或 `notFound` 状态；确定后仅返回临时 `entityRef` 与对象类型。不回传候选身份列表。
- 适配来源：`PersonnelRepository.watchEmployees`、`VehicleRepository.watchVehicles`。现有模糊搜索可能命中班组/区域/负责人；命中不等于用户身份已经唯一确定，必须使用结果集判断。

### 7.2 `getEmployeeMonthlyAttendance`

- 输入：`employeeRef: string`、`yearMonth: string`、`attendanceGroupRef?: string`。组引用缺失时在本地推导/选择，不让模型生成数据库组 ID。
- 本地输出：`employeeLabel/groupLabel`、`yearMonth`、`attendanceDays`、`leaveAndRestDays`、`overtimeMinutes`、本地明细引用、口径、时间和完整性提示。
- 模型投影：该人员临时引用及第 3 章规定的四项考勤汇总字段、受控状态/口径。完整性未评估时只允许描述“当前已登记汇总”，不生成全月完整性结论。
- 只读适配器需要拼接月表与加班数据，并核对查询条件和快照。不得调用工资生成、月汇总生成、名单增删或考勤保存。

### 7.3 `getVehicleAnnualRepairSummary`

- 输入：`vehicleRef: string`、`year: integer`。
- 本地输出：车辆本地标签、`year`、`completedRepairCount`、`actualAmountCents`、`currency=CNY`、维修单明细引用、`sourceRuleId=vehicle_repair_completed_report_year_v1`。
- 模型投影：临时车辆引用、年份、单数、实际金额和单位/口径，不含单号、车辆身份及故障文本。
- 本地实现复用维修费用分项并关联同口径维修单数；必须过滤 `sourceType=repair`，不能把 `list()` 全部费用相加。单数与金额来自相同快照和过滤条件。

### 7.4 `getAnnualVehicleRepairRanking`

- 输入：`year: integer`、`limit?: integer`、`cursor?: string`。首次查询无游标；不支持任意状态或用户指定 SQL 排序。
- 本地输出：`rows[{vehicleRef, vehicleLabel, rank, completedRepairCount, actualAmountCents}]`、全量车辆数、返回数、分页信息和口径；同一结果集中匿名代号稳定映射车辆。
- 模型投影：车辆标签替换为匿名 `alias`，仅保留第 3 章排名字段和覆盖信息。后续追问“第一辆”使用本地排名映射解析，不能重新按当前页面车辆猜测。
- 需要新增本地只读聚合适配能力；现有仓库未确认已有同名年度排名接口。可按当前仓库能力组合，最终实现优先使用有范围的读取，避免无界模型上下文或逐车网络调用。

### 7.5 `getLocalResultDetails`

- 输入：`resultRef`、`detailType=attendanceDays|overtimeRecords|repairOrders|repairCosts`、可选本地分页游标/维修单引用。
- 本地输出：与该结果条件和授权业务范围一致的明细；不能通过修改引用查看其他对象或年份。明细过期先刷新，不与旧汇总拼接。
- `attendanceDays`：日期及上午/下午状态；`overtimeRecords`：日期、起止时间、时长；`repairOrders`：报修/完成日期、状态、实际金额及本地详情入口；`repairCosts`：原业务费用明细。
- 备注等可继续在原业务页面查看。此 Tool 不注册为模型可自由调用的明细导出能力；外发明细由第 3.4 节另行投影和单次确认。

## 8. 结果卡片、来源与导航

卡片由结构化本地结果渲染金额、日期、排名和状态。模型文字与卡片分区展示，不覆盖卡片事实；模型未返回时卡片仍然可用。流式阶段可显示理解/查询状态，不提前输出未经本地结果支持的业务结论。

每张卡片具备：查询对象、年月、明确口径、查询时间、本地明细/来源、刷新和错误状态。金额以整数分存储/运算、人民币格式展示；考勤按天显示，可含半天；加班按分钟存储并格式化为小时/分钟。

| 结果 | 已有来源入口 | 当前能力与设计缺口 |
|---|---|---|
| 月度考勤 | `/attendance/monthly-table?month=YYYY-MM` | 当前路由支持月份，不直接支持人员定位与组参数；首期跳转前在本地传递选组状态，人员定位若需新增应作为显式路由/状态适配设计，不假称已有能力 |
| 加班记录 | `/attendance/overtime` | 当前入口无人员/月过滤参数；首期本地卡片保证精确条件，原页面跳转说明可能需要手动筛选；新增精确定位列为明确适配任务 |
| 单车维修 | `/vehicles/:vehicleId?tab=repair` | 支持车辆和维修 Tab；现有 `year` 参数用于油耗初始化，不能假称能筛选维修年份 |
| 单车费用来源 | `/vehicles/:vehicleId?tab=expense` | 可打开费用分析 Tab，但现有路由未为费用年份提供初始化能力；如需保留查询年份需显式补参数与页面初始化适配 |
| 维修单 | `/vehicles/repairs/:repairOrderId` | 已有按维修单 ID 打开详情的路由；只在用户点击时使用本地 ID |
| 全车维修 | `/vehicles/repairs` | 已有全车维修单页，不等同于年度排名页；排名由助手结果卡片提供 |

导航必须由 App 构造固定路由，模型不得返回任意 URL 让 App 执行。跳转原页的已有编辑按钮仍是原业务行为，不扩大助手 Tool 权限；助手不得自动触发保存。

## 9. 会话、失败与执行边界

- 历史在本机保存问题、查询条件、必要卡片快照、查询时间与执行状态；支持删除单会话和全部助手历史，不影响业务数据。存储方案与迁移范围在开发设计中明确，不在本文擅自承诺无需数据库变更。
- 历史卡片标注“历史查询”，恢复会话不把快照当最新结果。用户再次查询或刷新时重新读取业务数据；原有查询时间保留在旧消息中。
- 模型上下文按本轮必要条件、最近必要用户输入、允许外发汇总重建。不得把包含真实姓名/车牌的本地卡片文本、候选列表、完整 ToolResult、已授权明细或整段历史直接回放给模型。
- API Key 存入安全存储，不进入业务数据库、普通配置、会话、导出或普通备份。备份不自动包含助手历史和授权明细；若未来支持会话备份，应先定义范围。
- 日志仅记录受控事件、Tool 名、状态、耗时、Provider 和可获得的 Token 用量，不记录消息正文、业务结果、Key、完整请求/响应或原始异常。费用统计无官方计量或未配置价格时显示未知，不显示为零。
- 业务记录、用户备注、Tool 返回文本均不构成系统指令，不能改变 Tool 白名单、外发字段或授权范围。
- 取消/超时以请求标识使迟到响应失效。模型解释失败保留本地卡片；本地查询失败不得编造结果。重试由用户触发，鉴权失败引导密钥设置，首期不自动切换 Provider。
- 查询中收起悬浮窗不会重复调用；应用重启不自动恢复收费请求。单任务调用与时长上限应在开发设计中集中配置；参数值由实际接入验证确定，不在文档中冒充已验证性能。

## 13. 验证场景与验收记录

### 13.1 必测任务

| 类别 | 最小覆盖 |
|---|---|
| 考勤 | 指定人员月份；同名候选；缺少年份；同月多组；不在名单；部分未登记；入离职边界；请假/休息合计；加班分钟一致；“那李某呢”继承条件 |
| 单车费用 | 报修与完成跨年；未完成单排除；已完成零金额；无单；申报/实际金额不同；未付款单；已删除单/车；不混入保养油耗和备件重复费用 |
| 排名 | 完整集合后排序；金额并列；全零无记录；零金额有记录；多页不漏项不重复；匿名代号追问；刷新后旧游标失效；停用未删除车辆仍在集合 |
| 数据发送 | 捕获脱敏后的请求并断言默认字段白名单；默认不发送候选身份与明细；确认后仅发送选定字段/记录；取消不发；重试重新授权；历史不重放已授权明细 |
| 悬浮与上下文 | shell 内外切换；键盘/弹层/返回键；离开 App 不显示；收起展开不重复请求；页面切换不偷换对象；关闭悬浮窗不删除历史 |
| 失败与历史 | Key 无效、超时、格式错误、本地查询失败；模型失败保留本地结果；取消后迟到响应无效；恢复历史标注时间；刷新取得新数据；删除助手历史不改业务表 |

本地测试使用隔离夹具，不往现有设备业务库注入演示数据，不清空或重建现有设备业务数据。真实云端验证仅使用用户允许外发的内容，不能把生产明细当作默认测试载荷。

### 13.2 验收方法

- 业务准确性：在同一数据快照、相同对象/时间与固定口径下逐项比较；不能用月考勤表合计对比报表纯请假，或用已完成单数对比全部维修单数。差异必须解释或修复后复核。
- 只读与外发边界：对应自动化断言全部通过，业务表无非预期变化；模型请求中不出现默认禁发的数据库字段。
- 实用性：选取相同任务，记录现有页面操作与助手流程的完成情况、耗时、澄清/纠正次数；计入冷启动、选对象及等待模型时间，分别记录入口类型。
- 性能/费用：记录实际响应耗时和可获得的 Token，用量未知就标注未知；不在尚未实测时承诺固定速度或费用。
- 用户体验：由本人试用确认两类任务稳定、省时。暂未约定 95% 成功率或 30% 提速等数值门槛，不把此前建议值写成已确认指标。
- 回归与设备：代码针对性检查通过后，完成必要业务回归，再单独验证悬浮窗、键盘、返回键与路由行为；文档/单元测试通过不代替设备交互验证。

验收记录建议字段：任务编号、场景、前置条件、数据快照、预期、实际、是否完成、是否正确、耗时、澄清次数、纠正次数、外发字段检查、证据位置。没有实测数据的项目明确标为“未验证”。

## 14. 后续设计待落定项

下列内容属于后续交互与开发设计，不改变本轮已确认产品范围：悬浮窗具体尺寸/位置与无障碍行为；精确导航的最小参数适配；查询快照实现；会话存储/删除和迁移方案；模型版本与当前官方接口能力；请求时长/调用上限与费用展示方案。

如设计时必须新增外发字段、引入业务写入、改统计口径或扩展系统级悬浮范围，需提出具体变更，按一次一个问题的选项交互确认。普通实现细节在已授权范围内自行落实，不重复询问已确认决策。
