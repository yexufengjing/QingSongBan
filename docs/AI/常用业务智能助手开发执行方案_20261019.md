# 常用业务智能助手开发执行方案

日期：2026-10-19。状态：开发中，尚未验收。

## 本轮授权与目标

用户选择按业务域完成查询、解释、来源和验收，最终交付自用 APK。用户授权在问答实测前向 App 补充中文模拟使用数据，并要求独立开发节奏、不再中途询问。生产代码和测试分别交由两位 GPT-6 luna/high 子代理，主代理负责划分、审查、进度及串行验证。

用户追加确认：开发任务参照先前“一页结论性概览、分任务详述”的全部任务，范围包含高频业务闭环、系统交互和最终 APK，不仅新增助手入口。

沿用业务只读边界、现有 DeepSeek BYOK 和 App 内助手入口。保留已验收车辆费用多轮 Agent、考勤、年度维修及排名能力；不升级依赖、不改变业务保存规则、不发布 GitHub。

## 分域交付与验收

| 阶段 | 交付 | 验收重点 |
|---|---|---|
| A | 人员、考勤和工资查询、异常解释及来源 | 同名/缺记录、金额与考勤依据、改人改月及跨域切换 |
| B | 库存、采购和福利领取查询及联查 | 库存不足关联采购、采购/领取/入库状态区分、数量与来源 |
| C | 车辆维修与提醒查询、园林维修台账及价格比较 | 保留旧 Agent、金额/次数/比较口径、来源正确 |
| D | 中文数据实际加载、真实模型问答、系统交互和 APK | 先有样本再问答；模拟数据与既有数据共存；构建安装与核心流程 |

具体交付对应原六项任务：①本文件和逐场景验收表固定范围；②人员档案、考勤、工资的查数/解释/来源；③库存、采购、福利查询与关联；④车辆维修进度、提醒和园林维修台账/价格；⑤考勤→汇总→工资→导出、采购→领取→分批入库→撤销、园林录入/编辑/附件/分析，以及OA、通知、文件、相机相册、备份恢复等关键系统交互；⑥固定源码和校验值的自用 APK、覆盖安装与交付说明。此前四阶段是执行分批，不缩减这六项范围。

新增领域必须使用语义理解和有效上下文，不能仅靠关键词路由或增加入口宣称完成。统计由本地业务工具计算；来源由本地构造；用户主动输入外的信息按已有白名单约束外发。

## 模拟数据

新增默认关闭、重复启动不重复插入的演示开关。复用既有 schema 和业务仓库，记录带中文演示标记和可识别编号，覆盖当前/上月、正金额、库存及采购状态、考勤和工资、福利、车辆及园林维修。不得改写现有记录、清空数据库、卸载 App、读取或导出 Key。用户本轮对模拟数据的明确授权覆盖此前不造数据的限制。

## 分工与检查

- implementation：全部生产代码与模拟种子，不编写测试。
- tests：必要业务测试、回归与设备验收脚本，不修改生产代码。
- 主代理：审查语义与业务边界，统一串行执行 Flutter 命令、构建、安装、真实模型验证及交付记录。

只增加能够发现业务计算、上下文、来源或数据保护错误的测试；不增加实现镜像、重复字段断言或无价值覆盖。保留有效既有测试，失败按原因处理，不以删除测试获得通过。

验收分别记录源码、自动检查、模拟数据加载、模型问答、APK、设备交互和用户体验；用户离线期间不代替用户宣布本人体验验收通过。物理手机无连接时先完成现有模拟器验证，不声称真机已验收。
