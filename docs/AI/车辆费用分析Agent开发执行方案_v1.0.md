# 车辆费用分析 Agent 开发执行方案 v1.0

日期：2026-10-18。状态：实现、相关自动检查、APK构建覆盖安装及模拟器真实模型复测已完成；用户明确确认“达到预期，可以验收”，本轮体验验收通过。证据见 `docs/acceptance/vehicle-expense-agent/checks.md`。

依据：[已确认的行为与验收草案](车辆费用分析Agent行为与验收草案_v0.1.md)。上一轮增量版自动验证记录保留，其体验验收未通过，不能作为本轮通过依据。

## 1. 交付目标与范围

车辆页输入“这辆车最近怎么这么费钱”，直接开始分析：理解模糊条件 → 自主选择只读工具 → 根据结果决定对比、追查或结束 → 输出可核对的结论。支持“只看维修”“换上个月”“和同类车比呢”连续修正；只有缺少唯一车辆等关键歧义才追问。

保留考勤、单车年度维修、全车年度维修排名及来源导航。复用 DeepSeek BYOK 与 App 内浮窗，不改数据库结构、业务保存规则、依赖或其他页面设计。不读取或导出已保存 Key，不向现有模拟器业务库写测试记录。

## 2. 接口变化与职责

以下是本轮必须提供的契约职责。

| 接口 | 输入 | 输出与约束 |
|---|---|---|
| 语义入口 | 当前问题、当前日期、匿名页面/会话条件 | 区分旧查询、费用分析、条件修正和关键歧义；命名车辆在本地解析，页面/会话车辆 ID 不外发 |
| Agent Provider | 工具定义、当次任务消息及匿名工具结果、取消令牌 | 模型选择的工具调用或结束；携带调用 ID，参数需本地校验 |
| 期间费用工具 | 已解析的本地车辆、日期范围、费用类别 | 本地计算金额（分）、次数、数据覆盖；日级与月级分开 |
| 前后期比较工具 | 本期与同口径前期、类别 | 金额差、次数差、可计算时的增幅；零基期、无记录和不完整分别标识 |
| 变化来源工具 | 同车辆、期间与类别 | 分类贡献、次数与集中程度等结构化依据；不读取外发单据备注/症状 |
| 同类车参照工具 | 本地车型、同期间/类别 | 匿名车辆参照、可用里程/工时/工作天数、可比性与缺口；期间不一致不生成单位成本比较 |
| 会话执行器 | 需求、提交时上下文快照、业务端口与 Provider | 按模型选择执行工具、反馈结果、提前结束；生成本地证据和来源，进度只展示动作摘要 |

业务工具不得接受任意 SQL、路由或模型生成的数据库 ID。上下文 ID、候选映射及来源路由留在本地；工具只能访问任务所需的只读业务接口。全局入口命名车辆、页面代词及已选车辆的短句追问都要覆盖，不能仅靠页面是否有车决定语义。

实现接缝：`AttendanceAction.queryVehicleExpenseAnalysis` 复用原语义分类入口；`IntentRequest` 补充匿名的上轮类别、期间、年月，支持短句条件沿用；`VehicleExpenseAgentProvider.completeAgentTurn` 负责多轮协议；`AssistantVehicleExpenseRunner` 校验并执行 `summarizeVehicleExpenses`、`compareVehicleExpensePeriods`、`inspectVehicleExpenseDrivers`、`comparePeerVehicleExpenses` 四个工具。前后比较和贡献计算由执行器结合本地结果完成。`VehicleExpenseReadPort` 由 `AssistantVehicleExpenseReader` 实现，提供期间聚合及同类参照。`VehicleExpenseAnalysisAnswer` 保存本地依据、参照、终态和仅含枚举名的已执行工具列表。

参数只含允许的期间、类别、可选明确年月和比较期间。明确自然月用 `yearMonth`（`YYYY-MM`）并在本地构造日期边界；上一自然月的对照是再前一个自然月。工具不接受身份参数，车辆在任务提交/候选选择时已本地绑定。

### 日期与统计口径

- “最近”默认包含今天的连续30个自然日，与此前连续30日对比；采用本地日期边界。
- 数据少时可补查90天，保留原30天问题并注明背景范围。明确月份则按自然月；历史年月、跨年、闰年由本地日期处理。
- 维修采用已完成、未删除单据及实际金额，按报修日期归属；保养按执行日期，手工费用按费用日期。
- 油费只有月度记录。展示月份及登记覆盖，不按月初整笔塞进滚动30天、不按日均摊。不同粒度不混算精确总额与增幅。
- 未登记不等于实际零支出；未完成月份与已完成月份比较需注明限制。无可比工作量时只作金额参照，不判定异常或归因驾驶行为。

### 数据外发白名单

允许：用户主动输入的问题、日期/月份、费用类别、汇总金额/次数、分类贡献、匿名参照代号、对齐期间的工作量、覆盖与可比性标记、必要的工具状态。仅发送当前任务所需字段。

不自动发送：数据库姓名、车牌、车辆名称/编号、内部 ID、逐条单据、备注/症状等自由文本。明细外发仍需单次确认具体字段和范围；本轮不依赖明细外发实现分析。金额、日期和比例必须能回指本地结果，不能把模型自由文本中的数字直接当业务事实。

### 协议与执行预算

继续使用 `deepseek-flash`、`/chat/completions`，明确关闭 thinking，采用官方工具消息协议：保留模型返回的 assistant 工具调用，再追加具有对应 `tool_call_id` 的 tool 结果；模型读结果后再次决策。不伪造模型未发起的工具调用消息。

每个任务最多6次模型请求、8次业务工具执行、120秒总预算。证据充分可提前结束，不机械跑满；达到预算、超时、断网或停止时保留已取得的本地依据与问题，不反复重试。现有单请求超时与传输取消继续生效。

官方核对（2026-10-18）：[Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)、[Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)。本轮不引入 Beta strict 或新 SDK。

## 3. 改动范围与执行顺序

| 优先级 | 工作 | 完成判据 | 预计顺序 |
|---|---|---|---|
| P0 | 契约、期间/粒度模型、匿名投影 | UI和核心共用类型；错误、覆盖、证据、取消均可表达 | 第1步 |
| P0 | 本地费用与对比工具 | 隔离库计算正确，原维修口径保留，油费和工作量不误配 | 第2步，与UI接缝准备并行 |
| P0 | 多轮 Provider、执行器、语义入口与会话修正 | 工具结果实际反馈模型，能依结果选择后续；命名/代词/短句可用 | 第3步 |
| P0 | 简洁进度、分析回答、证据与来源 | 一次输入后自主完成；可停止、返回来源、全屏/浮窗共享结果 | 第4步，契约固定后与核心并行 |
| P0 | 隔离案例与旧功能回归、构建覆盖安装 | 相关检查通过；失败明确区分本轮与原有问题 | 第5步 |
| P0 | 模拟器真实模型任务与本人试用 | 核实模糊需求/工具链/纠正/停止，最终由本人判断便捷性 | 第6步 |

代码集中在 `lib/features/assistant/domain`、`data`、`application`、`presentation` 和 `test/assistant`；仅必要时调整既有来源入口。核心与UI两条代码工作流由两名 GPT-6 luna/high Agent 执行，主 Agent 负责方案、审查、串行 Flutter 检查、设备验证和交付记录。时间以阶段推进，不以未经验证的工时承诺替代完成判据。

## 4. 验收任务

| 编号 | 场景 | 关键断言 |
|---|---|---|
| A01 | 车辆页“最近怎么这么费钱” | 一次输入、无需预填条件，默认30天；出现真实工具调用及结果反馈 |
| A02 | 全局入口命名车辆；同名/缺车 | 本地正确解析；仅必要时一次候选选择，不把身份自动外发 |
| A03 | “只看维修”“换上个月”“和同类车比呢” | 沿用正确车辆，改变范围并重新读数据；不重复问已知条件 |
| A04 | 费用增长集中一类 | 模型根据结果追查；回答以本地贡献依据说明变化，不只复述合计 |
| A05 | 月度油费、跨月30天、未完整月 | 不伪造日级油费；口径与覆盖清楚，合计和比例可复算 |
| A06 | 同类车工作量差异、分母缺失/错期 | 同期间才算单位成本；不可比仅作参考，无无据异常结论 |
| A07 | 无记录/少记录/前期零/无明显上涨 | 区分缺数据与零，必要时查90天背景，不附和编造原因 |
| A08 | 换车、在途进入另一页、明确纠正 | 当次请求保持提交快照；下一次使用新选择；纠正后对象正确 |
| A09 | 停止、超时、断网、超预算 | 停止后不再继续调用；保留已取得事实，可继续或重试 |
| A10 | 外发字段、伪造工具/参数、无依据数字 | 白名单投影和本地参数/证据校验生效，日志无 Key 或原始业务明细 |
| R01 | 旧考勤/年度维修/排名/分页与来源 | 原有功能及上下文行为回归通过 |
| R02 | 浮窗/全屏、键盘、菜单返回和来源返回 | 共享会话和草稿，返回顺序正确，查看来源不触发重查 |

正金额、费用结构变化、里程差异及缺失场景只用隔离测试库。模拟器当前已有数据能证明的范围单独记录，不能用空库实际运行代替正金额分析验收。真实模型记录只留必要的工具名、匿名参数/汇总、调用次数、终态与证据校验，不保存 Key、原始响应或内部推理。

每项记录“通过/失败/未验证”及证据位置。最终分别报告源码、测试、APK、覆盖安装、模拟器真实模型和本人体验验收；未获本人认可前不称体验验收通过。
