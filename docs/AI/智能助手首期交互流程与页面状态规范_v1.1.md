## 1. 这次改变什么

用户指出：逐步选任务、补年份、选人员、选考勤组、点击继续的时间，已足够直接操作原 App。已确认的体验目标是：直接说一句需求，助手结合上下文给结果；只在确实不能确定时简短追问。

首期仍限本人使用、DeepSeek BYOK、业务只读、个人月度考勤/单车年度维修/全车年度排名。外发汇总白名单和明细单次授权继续生效。本轮改变交互默认路径，不增加写入或跨 App 悬浮能力，也不声称复现了企业微信的具体实现。

| 项目 | v1.1 交互 |
|---|---|
| 起始 | 直接进入聊天，输入框可用；示例问题是可选的一键提交，不是必经菜单 |
| 默认主线 | 输入一句话 → 简短查询状态 → 直接答案；无需选择任务、补全表单或确认查询条件 |
| 结果 | 先给关键答案和实际对象/时间；明细、口径与原页面按需展开 |
| 缺年份 | 当前输入 > 本轮年份 > 页面年份 > 设备当前年份；自动采用后在答案中注明 |
| 纠正/追问 | 直接说“查去年”“那李四呢”；沿用其他适用条件，执行新查询 |
| 真歧义 | 同名且上下文无法唯一确定等情形才追问；候选在当前消息中展示，点选即继续查询 |
| 浮窗 | 同一聊天会话的 App 内便捷视图，输入/答案不换成另一套操作流程 |

本文后续均按此表执行；不保留“选择后再点继续”作为常规路径。

## 2. 标准对话与操作预算

以下为交互示意，人名是虚构占位，数值 `—` 由真实实现中的业务结果填入，不代表项目现有数据。

### 2.1 个人考勤：一句话直接回答

```text
用户：查张三9月考勤
助手：张三在 2026 年 9 月，出勤 — 天，请假与休息合计 — 天，
      加班 — 小时 — 分钟。
      按今年查询 · 当前已登记汇总
      [查看明细] [口径与来源]

用户：查去年
助手：已改查张三 2025 年 9 月：……

用户：那李四呢
助手：李四在 2025 年 9 月：……
```

没有年份上下文时才用设备当年；上例年份以 2026-10-17 为说明。真实显示随提交时设备本地日期解析。“去年”是设备当前年份的上一年，不是每追问一次就将上一结果年份再减一。

### 2.2 页面内查询

```text
从某车详情打开浮窗：
用户：今年维修花了多少
助手：〔当前车辆〕2026 年已完成维修单实际费用 ¥—，共 — 单。
      按报修年份统计
      [查看维修单] [口径与来源]
```

页面已提供车辆，用户不必重复输入车牌。不因打开助手就自动查数据或调用模型；提交问题才启动任务。

### 2.3 只在必要时追问

```text
用户：查张三9月考勤
助手：有两位张三，你指哪位？
      [张三 · 编号… · 班组A] [张三 · 编号… · 班组B]
用户：点击其中一个
助手：直接返回该人员当月汇总。
```

候选仅本地显示。点选本身就是答案，不再出现“已选择，点击继续”。仍支持用户直接回复编号或其他信息；候选多时提供本地搜索，不列出全部数据库对象给模型。

### 2.4 体验验收预算

- 对象和月份可解析：提交一次问题即可获得结果，中间零次必填点击。
- 缺年份：零次额外点击；在结果说明采用的年份，允许一句话纠正。
- 必须消歧：一次候选点击后直接继续；不再额外确认同一选择。
- 查看明细：结果下点击一次展开；返回仍在同一条消息附近。
- 不为缩短流程而放宽业务身份或明细外发边界。错误匹配率和纠正次数与耗时一起记录，不能只统计点击减少。

## 3. 系统自动处理与必须追问的边界

| 情形 | 处理 |
|---|---|
| 月份明确、年份省略 | 沿用本轮/页面年份，否则当前年；在结果中显示，不先确认 |
| 对象已在本轮明确 | 同类型追问沿用对象；本次新对象优先 |
| “今年”或“去年” | App 按提交时设备日期确定自然年，不依赖模型内置日期 |
| 省略对象，但相关页面提供唯一对象 | 直接使用页面对象，并在答案中点明 |
| 全局新对话只说“查9月考勤” | 无法确定人员，简短询问人员；不提供任务/年份/考勤组整套表单 |
| 本轮对象与页面对象冲突 | 按当前明确输入和本轮适用上下文处理；只有语义确实无法决定时简短问一次 |
| 同名且不能由上下文唯一确定 | 对话内本地候选，用户点选后直接查询 |
| 人员有多个有效考勤组 | 优先明确的组；否则适配器验证同人同月记录与汇总是否一致。一致则仅返回一次个人汇总，来源中列组；不把相同记录叠加。确实存在会影响结果的差异才追问 |
| 完全缺少月份且上下文没有月份 | 询问“查哪个月？”提供本月、上月和月份选择；不擅自定义新的隐含月份规则 |
| 超出首期场景/口径 | 一句话说明限制并给相关原页面入口，不展开新功能流程 |

异常数据不因助手自动处理就被修正；适配器无法证明多组结果一致时，继续使用既有明确组口径或追问。组自动处理属于新只读适配能力，尚未实现/验证。

## 4. 聊天布局与信息层级

### 4.1 主界面

顶部只保留返回/收起、助手名称和更多；历史与设置收入更多。主区域是一条连续对话流，底部始终是问题输入和发送/停止。

空会话给一句能力说明和两三个可点击示例，例如“查张三9月考勤”“今年哪辆车维修最贵”。点击示例直接提交完整演示问题，不打开任务向导。已有消息后示例收起，让结果成为主体。

不默认显示大块条件条、执行步骤表、Tool 名、Provider 元数据、完整口径和多排按钮。查询时仅一条“正在查询考勤…”或“正在查询车辆维修费用…”，支持停止。

### 4.2 答案消息

第一段直接回答需求；关键业务数值由确定性本地结果绑定展示，不让模型改写为不同数字。姓名、车辆身份从本地绑定恢复在答案标题/结构化文本片段，不向模型附加真实身份，也不靠整段字符串替换恢复身份。

答案下面只保留两项主要入口：“查看明细”“口径与来源”。其中：

- 本地明细以内联展开或轻量明细页承载，不发给模型。
- “口径与来源”展开时间、采用的默认条件、统计规则与原页面入口。
- 查询时间和“历史结果”标识可见；完整技术规则不占据答案首屏。
- 考勤沿用“请假与休息合计”；未登记不等于缺勤，完整性未评估不说“考勤正常”。
- 排名直接回答最高费用车辆；并列第一必须说明并列。当前页名次/行由本地完整聚合产生，分页详情再展开。
- 模型解释失败时用本地汇总组成简短答案，旁边提示“文字解释暂不可用”；不能要求重新完成整条查询才能看结果。

## 5. 追问、纠正与会话连续性

每次追问产生新一条答案，旧答案保留其年份和查询时间，不原地覆盖成另一人/另一年。兼容的省略输入沿用相关条件；跨场景切换清除不适用条件。

“查去年”保留上一条任务类型、对象和月份，替换年份；“那李四呢”保留月份和已采用年份、替换人员，并重新推导其有效名单。纠正后答案第一句点明新条件，用户能立即判断是否正确。

用户可在当前输入框继续说话，不需要退回首页、重新选择任务或重建会话。运行中可停止后重新提交；取消标记使旧响应不能覆盖新任务。一次用户提交及其必要 Tool/解释调用是同一任务，不因视图切换重复启动。

## 6. 悬浮、明细和授权

App 内浮窗仍支持拖动、收起和隐藏；提供靠左/靠右替代拖动。和独立页共用一条对话，转全屏/返回不丢消息和输入。键盘遮挡时保持输入可见，可用高度不足再转全屏。离开 App 不显示，不申请系统悬浮窗权限。

普通查询沿用已确认的默认汇总白名单，不在每条查询前弹确认。只有请求模型分析逐条明细时，才展示接收方、实际匿名字段、记录范围与发送预览，单次确认。取消/返回不发送，刷新、改范围或重试需重新确认。这一步不能因“追求快捷”而删除。

本地历史打开不自动联网；旧答案标注历史时间，用户说“重新查一下”或点“刷新本地结果”才读取当前数据。无记录、本地失败、模型失败用不同短消息表达，恢复按钮明确其作用，不让错误替代已有有效答案。

## 7. 低保真预览与验证

预览重点是实际路径：

1. 点击示例或输入支持的考勤问题，直接出现查询状态与答案，没有中间选择页。
2. 输入“查去年”，答案沿用对象/月并使用设备当前年份的上一年。
3. 输入“那李四呢”，答案继续沿用修正后的年份与月份。
4. 用“同名歧义”评审场景模拟唯一必要追问，点候选后直接出结果。
5. 打开明细/来源，返回同一对话；请求分析明细才出现单次授权。
6. 全车年度排名和单车问题直接回答，页面上下文示例可省略车辆名。

HTML 使用虚构人名与 `—` 数值占位，仅模拟上述已定义输入模式，不接模型/数据库，不采集真实密钥。可检查 390dp/320dp 线框宽度和浮窗模式。任意自然语言理解、真实金额、设备键盘/返回/读屏及真实任务耗时仍属未验证。

## 8. 后续交付标准

UI 视觉设计以本稿的连续聊天为主屏，使用现有 App 的视觉语言。三类结果共享答案样式；不再画默认的“年份选择页→人员选择页→考勤组选择页→继续”主线。

开发按“自然语言意图 → 本地上下文解析/默认值 → 必要消歧 → 业务查询 → 简短答案”设计。默认年份来源可追踪、实体引用不越界、数值仍由本地业务代码计算；外发投影与本地完整结果独立。

验收对照原 App：正常路径零次中间必填点击；必要消歧一次选择即继续；对比完成耗时、选错对象/年份和用户纠正次数。增加了默认值也应记录误用情况，不能以少问为由隐藏错误。

本轮只修订文档和线框；原 v1.0 保留并标记替代关系，未改 Flutter、现有业务接口、数据库或设备数据。
