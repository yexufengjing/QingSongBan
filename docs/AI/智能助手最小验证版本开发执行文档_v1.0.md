## 1. 目标与依据

本版本回答一个问题：**用户说一句考勤需求后，真实模型和 App 能否准确查出结果，并比直接操作页面更方便？**

执行依据：

- [首期场景与业务 Tool 契约](首期场景与业务Tool契约_v1.0.md)，含已同步的对话优先修订。
- [首期交互规范 v1.1](智能助手首期交互流程与页面状态规范_v1.1.md)：一句话直接回答、继承上下文、缺年份默认、必要时才追问。
- [交互线框 v1.1](wireframes/智能助手首期交互线框_v1.1.html)仅用于理解交互，不得把其中关键词模拟器移植成真实语言理解实现。

本文件确定“最小验证版本”的实现范围、接口、执行顺序与验证任务；完整首期的车辆、浮窗和历史等目标仍然保留，按验证结果随后推进。业务口径和数据发送边界继续遵守 Tool 契约；用户后续明确指令优先。

### 3.1 单人快照的具体实现约定

新增 `AssistantAttendanceReader`，通过现有 `AppDatabase` 进行有范围的只读读取，不改旧页面默认行为：

1. 在同一只读事务中读取目标人员、该月有效名单、当月考勤、相关离职记录和当月加班；时间范围为本地月初（含）到下月月初（不含）。
2. 用已有 `MonthlyAttendanceTableRow` 装配目标人员记录，复用上述计算和 `cellForDay()`。不复制出另一套请假、入离职或考勤公式。
3. 多组指向同人同月相同记录/规则/结果时，只返回一次个人汇总，来源保留多个组；加班只累计一次。不把组行相加。
4. 明确组与该人当月有效名单不一致时，不静默换组；若能按用户明确的人和时间找到有效组，则说明实际来源，否则返回受控选择/名单错误。
5. 多组、离职关联等来源无法验证一致时，返回必要消歧或 `DATA_CONFLICT`，不能任取第一条；不在本任务修复历史业务数据。
6. 不在月名单返回 `NOT_IN_ROSTER`；有名单但没有记录显示未登记，不按“零出勤且正常”解释。完整性默认为 `notEvaluated`。
7. 事务内使用单次 `select/get`；不要在事务内等待旧仓库 `watch().first` 而引入流订阅与事务等待。旧 `watchTable().first` 只在事务外作为测试参照。

## 4. 最小架构与接口

```text
AssistantPage / 月表页面上下文
               ↓
AssistantController
  明确追问：本地上下文处理（查去年 / 重新查等）
  其他表达：DeepSeekProvider.parseIntent（真实模型）
               ↓
AssistantContextResolver + 本地实体解析/必要选择
               ↓
AssistantAttendanceReader.readMonth（业务只读）
               ↓
AssistantAnswerFormatter（绑定真实数字）→ 对话答案与本地明细
```

正常查询默认一次模型解析调用；正确数值与简短自然语言答案由本地格式化产生。这样同时验证真实理解与真实查询，避免每次都等待第二轮模型来复述数值。只有用户主动要求“解释这个汇总”时，才可调用第二次模型，且只发汇总白名单；最小版本不开放明细外发。

### 4.1 对外模块接口（拟定）

以下是实施目标签名，当前尚不存在。命名可随仓库规范微调，职责与边界不得丢失。

```dart
abstract interface class AssistantKeyStore {
  Future<bool> hasKey();
  Future<String?> readKey(); // 仅 Provider 使用，不暴露到 UI 状态
  Future<void> saveKey(String key);
  Future<void> removeKey();
}

abstract interface class AIProvider {
  Future<AttendanceIntent> parseIntent(
    IntentRequest request, RequestToken token,
  );
  Future<ConnectionCheck> checkConnection(RequestToken token);
  Future<SummaryExplanation> explainSummary(
    AttendanceOutboundSummary summary, RequestToken token,
  );
}

abstract interface class AttendanceReadPort {
  Future<EmployeeResolution> resolveEmployee(EmployeeSelector selector);
  Future<AttendanceReadResult> readMonth(ResolvedAttendanceQuery query);
}

// 本地确定性模块，不调用模型/网络/写入接口
abstract interface class AssistantContextResolver {
  ResolvedIntent resolveContext(
    AttendanceIntent intent, AssistantSessionContext session,
    AssistantPageContext? page, DateTime now,
  );
}

abstract interface class AssistantAnswerFormatter {
  AssistantAnswer formatAnswer(AttendanceReadResult result);
}

// Controller 的用户事件
abstract interface class AssistantActions {
  Future<void> submit(String utterance);
  Future<void> selectCandidate(String candidateRef);
  Future<void> refreshResult(String resultRef);
  void updatePageContext(AssistantPageContext? context);
  void cancelCurrentTask();
  void clearSession();
}
```

`RequestToken` 是本地请求序号/取消状态，不是鉴权 Key；取消时使序号失效并中止可中止的 HTTP 请求。每个异步结果检查是否仍属于当前任务。`DateTime now` 必须可注入，年份边界测试不读不受控的系统时钟。

### 4.2 类型约定

| 类型 | 必备字段与含义 |
|---|---|
| `IntentRequest` | 本次用户文本、受控的最近查询类型/年月、页面年月/是否有对象、解析所需本地日期；不含数据库姓名/编号/候选/原始记录 |
| `AttendanceIntent` | `action`、`employeeText?`、`year?`、`yearReference`、`month?`、`clarification?`；模型仅提供待校验意图，不提供业务金额/考勤数值 |
| `AssistantPageContext` | 本地 `module/page/yearMonth/groupId?/employeeId?`，有明确来源才填人员；不原样外发 |
| `AssistantSessionContext` | 最近已校验、可继续查询的人员本地引用、年月和来源；成功及`NOT_IN_ROSTER`业务空结果可供换年/刷新继续，卡片仍显示真实状态；取消、无效参数、人员失效、网络或读取故障不覆盖已有条件 |
| `EmployeeResolution` | `unique/candidates/notFound`；候选本地标签、会话绑定不透明引用。用户点选立即继续，无额外确认 |
| `ResolvedAttendanceQuery` | 已校验内部人员 ID、有效年月、明确/可验证的组范围、本地时区、字段来源；仅业务适配层使用 |
| `AttendanceReadResult` | 成功/空/不在名单/冲突/失败；人员/组本地标签、年月、三项汇总、本地明细、口径、查询时间、完整性状态 |
| `AttendanceOutboundSummary` | 仅 `yearMonth/attendanceDays/leaveAndRestDays/overtimeMinutes` 及必要非身份单位/口径；不从原实体通用序列化 |
| `AssistantAnswer` | 本地事实片段、可选模型解释、实际对象/年月、默认值说明、查询时间、本地明细/来源动作 |

身份解析：姓名精确匹配优先，编号按编号查；其余模糊匹配只形成候选。同名不根据模型自信程度猜选；来自明确上下文的对象可直接绑定，删除状态需复核。新人员追问清除旧人员组归属，再推导新人员当月名单。

### 4.3 时间与追问规则

| 输入 | 确定性处理 |
|---|---|
| “查张三9月考勤” | 年份沿用本轮/页面，否则当前年；答案显示具体年月及默认值来源 |
| “查去年” | 在上一考勤查询中替换为设备当前年份减一，保留人员和月份；重复说去年不累计减年 |
| “那李四呢” | 保留最近可继续查询的年月，替换人员；必要时消歧一次 |
| “重新查一下” | 重新读取同条件当前数据，不复用旧快照冒充最新；无需模型再次推理已确定条件 |
| 缺人员 | 页面/本轮无法确定时，只问人员；候选/文本回复后接着原任务 |
| 缺月份 | 上下文没有月份才问；本月/上月按钮本地明确年月，不默认猜测月份 |
| 明确无效年月或冲突字段 | 受控提示修正，不能回落当前年掩盖错误 |

明确且无歧义的短追问可以本地执行；任意其他句子仍通过真实模型解析。不得扩大正则列表逐条背答案来通过评测，须记录每轮是 `localFollowUp` 还是 `modelParsed`。

业务空结果仍应支持纠正：第一次默认按今年查某人，但其不在今年该月名单时，答案必须保持`NOT_IN_ROSTER`、汇总为空；随后说“查去年”仍沿用刚才已校验的人员和月份，无需重复姓名。此规则用于兑现默认年份可一句话纠正，不把技术错误或无效对象当成可执行条件。

## 5. DeepSeek 接入协议与密钥

### 5.1 已核对的外部依据

2026-10-17 核对的[官方入门文档](https://api-docs.deepseek.com/)给出 `https://api.deepseek.com` 和当前 `deepseek-flash` 模型。验证版以该模型为初始配置，配置集中到 Provider，不散落业务层；实施时复核账号可用模型，变更时记录，不根据旧别名猜测。

[官方 Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)支持函数 Tool、`tool_choice`、`thinking` 和非流式请求；模型参数仍需 App 校验。本文使用正式端点、关闭 thinking、不依赖 Beta strict；不是已完成真实连接的结论。

### 5.2 网络与解析步骤

| 项 | 本版本约定 |
|---|---|
| 请求 | `POST https://api.deepseek.com/chat/completions`，JSON；Bearer Key 仅在鉴权 Header |
| 默认参数 | `model=deepseek-flash`、`thinking.type=disabled`、`stream=false`；解析输出上限先取 512 tokens，作为实施默认值、不是性能承诺 |
| 模型函数 | 只提供 `prepareAttendanceQuery` 参数准备函数，使用命名 `tool_choice`。这是模型意图协议，不是新增数据库操作能力 |
| App 业务 Tool | 本地校验参数后，映射到契约中的 `resolveBusinessEntity/getEmployeeMonthlyAttendance`；不让模型自由调用 Repository |
| 校验 | 必须恰好得到一个允许函数调用；解析其 JSON 参数，拒绝未知函数、未知字段、错误类型、非法年月及不一致的相对/绝对年份 |
| 无有效 Tool | 普通文本不能作为事实答案；返回“未能可靠理解，请换种说法”，保留问题。首次实现不做后台模型自修复循环 |
| 超时/停止 | 连接超时初值 10 秒、整次解析初值 20 秒，集中配置并用设备实测调整；用户可立即停止，未取消的远端处理不等于仍可更新本地任务 |
| 重试 | 不自动重试 401/限流/网络/格式失败；用户明确重试。候选选择不重做模型解析，只继续已解析查询 |
| 普通费用 | 普通自由查询一次解析请求；本地明确追问可零次；解释为用户主动另一次请求。记录实际次数和可获得 Token，不预先承诺费用 |

`checkConnection()` 使用同一正式端点与所选模型，发送不含业务内容的最短测试消息，关闭 thinking、不提供 Tools、限制输出；只验证鉴权和模型可用性，不以测试连接成功替代业务 Tool 验收。界面注明测试会发起一次真实请求，用户点击才执行。`explainSummary()` 同样使用该端点，但不开放 Tools，只接收白名单汇总；其输出单独展示，不替换本地事实片段。

模型函数参数的拟定 Schema：

```json
{
  "type": "object",
  "additionalProperties": false,
  "required": ["action", "employeeText", "year", "yearReference", "month", "clarification"],
  "properties": {
    "action": {"type": "string", "enum": ["queryAttendance", "changeYear", "changeEmployee", "refresh", "clarify", "unsupported"]},
    "employeeText": {"type": ["string", "null"]},
    "year": {"type": ["integer", "null"]},
    "yearReference": {"type": "string", "enum": ["explicit", "current", "previous", "inherit", "unspecified"]},
    "month": {"type": ["integer", "null"]},
    "clarification": {"type": ["string", "null"]}
  }
}
```

Schema 是本地校验契约；未启用 strict 不代表可省略校验。`yearReference=explicit` 才接受显式 `year`，相对年份由 App 计算；`clarification` 不允许成为任意业务执行指令。执行查询前必须得到完整有效内部条件。

解析指令明确：只理解用户意图，不计算事实；不存在的信息返回空值；不要要求用户提供能从受控上下文得到的年份。自由表达的含义由模型识别，默认值/实体绑定/业务规则由 App 决定。

“他/这个人”等指代表示继承本地对象，不作为姓名搜索词。每次解析请求重建必要上下文，不回放未配对的函数调用历史；参数准备函数的响应不直接作为用户事实答案显示。

### 5.3 Key 存储与依赖

网络优先用 `dart:io HttpClient`，加可注入传输边界用于测试，不增加 HTTP/Agent SDK。安全存储新增 `flutter_secure_storage`，以当前发布的 `11.2.0` 为候选锁定版本；真实实施先检查本地 SDK 兼容和依赖解算，再记录精确版本及 `pubspec.lock`，不为此升级既有技术栈。[发布方文档](https://pub.dev/packages/flutter_secure_storage)列出 Android 安全存储及备份约束。

- 只读写本应用 `assistant.deepseek.apiKey`；移除只删此键，不调用全局 `deleteAll()`。
- UI 只显示掩码/是否配置，允许粘贴；Key 不进消息、模型提示、日志、SQLite、普通配置、导出或测试记录。
- 当前 Android 最低版本 24；不新增生物识别或系统悬浮窗权限。保留现有 `allowBackup=false`，核对 secure storage 对应数据同时排除云备份和设备迁移。
- [backup_rules.xml](../../android/app/src/main/res/xml/backup_rules.xml)已排除多个存储域；[data_extraction_rules.xml](../../android/app/src/main/res/xml/data_extraction_rules.xml)现仅见 root 排除。按最终插件文件域，必要时只补密钥相关的 sharedpref/file 排除，不改变其他业务备份策略。
- App 手工备份沿用[现有白名单归档](../../lib/features/backup/application/backup_service.dart)，不加入 secure storage 或会话文件；不更换备份格式。
- 用户在 App 内配置真实 Key，不要求在聊天、源码、命令行参数或测试报告提交 Key。本次文档阶段不消耗真实 API。

## 6. 数据外发和可观察性

首次配置说明：用户主动提交文本将发给 DeepSeek；数据库身份不自动附加。解析只发送该文本和非身份的必要年月/任务上下文，不回放本地候选、卡片和完整会话。

默认答案由本地格式化，不需要把考勤结果发给模型才能显示。可选解释仅发送四项汇总白名单，不发送姓名、编号、组名、内部 ID、逐日考勤、加班明细、备注、工资或保险。用户请求解释明细时提示本验证版仅支持本地查看，不偷偷发送。

记录每轮：本地任务编号、解析方式、Provider/模型、成功/错误码、必要的调用次数、Token（可能未知）、理解耗时/本地查询耗时/首个正确答案耗时、澄清次数。持久日志不含用户原文、候选身份、数据库内容、Key 或原始请求响应。

测试环境可拦截虚构输入和隔离夹具的请求体断言白名单；真实使用环境不得开启全量 HTTP 调试日志。云端请求失败后只展示受控原因，不将 Provider 原始响应原样写日志或展示为业务答案。

新增路由需同步既有固定路由数量断言和用例表。全量测试中网络 Provider 一律使用 Fake，不能无意产生费用。`pub get` 后审查 lockfile，仅接受必要插件带来的依赖变化。

设备安装前确认当前设备ID、应用ID和版本；使用保留数据的替换安装，不卸载、不 clear data、不恢复覆盖业务库，不开启 `QSB_SEED_*`。安装后分别验证真实Key测试、考勤对话、页面年份、必要消歧、明细/返回、停止、网络失败及原月表编辑/导出原功能仍可使用。此阶段不实际修改设备考勤来证明查询刷新，可用自然发生数据或隔离设备/夹具验证。
