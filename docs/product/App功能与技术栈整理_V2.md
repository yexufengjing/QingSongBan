# 轻松办 App 功能与技术栈整理 V2

> 版本定位：第一阶段人员管理与临时员工模块的产品/业务规则基线文档。
> 
> 本版本在原方案基础上，重点重构考勤逻辑：采用“上午 + 下午”半天制作为基础考勤单元；引入考勤组与月度考勤名单；加班独立按分钟记录；同时保留人员档案、请假、离职、保险、月度汇总、Excel、本地提醒、备份恢复等能力。

---

## 一、第一阶段目标

第一阶段先开发“人员管理”，重点服务临时员工与现场人员的日常管理。

技术方案保持完全本地化：

- Flutter + Dart；
- Riverpod；
- GoRouter；
- Drift + SQLite；
- 本地定时通知；
- Excel 导入导出；
- 本地备份与恢复；
- 暂不接入云服务，不产生服务器费用。

本阶段包含五个主要业务部分：

1. 人员档案；
2. 考勤管理；
3. 月度汇总；
4. 社保保险；
5. 提醒事项。

请假、加班、离职统一从“考勤管理”进入，但在数据库中分别保存独立记录。

## 二、核心业务原则

### 1. 基础考勤以“上午 + 下午”两个半天单元为核心

每天不以“8 小时输入”为主要登记方式，而是拆分为：

- 上午状态；
- 下午状态；
- 加班记录。

基础状态包括：

- 未登记；
- 出勤；
- 请假；
- 缺勤；
- 公休；
- 停工；
- 未入职；
- 已离职。

统计规则：

- 上午出勤 + 下午出勤 = 出勤 1 天；
- 上午出勤 + 下午请假 = 出勤 0.5 天、请假 0.5 天；
- 上午请假 + 下午出勤 = 出勤 0.5 天、请假 0.5 天；
- 上午请假 + 下午请假 = 请假 1 天；
- 上午缺勤 + 下午缺勤 = 缺勤 1 天；
- 上午公休 + 下午公休 = 公休 1 天；
- 上午停工 + 下午停工 = 停工 1 天。

半天出勤在月表中显示统一“半天符号”，点击单元格后查看具体是上午还是下午。

### 2. “无出勤”不能一律视为请假

请假、缺勤、公休、停工必须在系统内部明确区分。

原因：

- 请假是已登记的请假行为；
- 缺勤是应到但未到；
- 公休是计划休息；
- 停工是单位安排停产、检修等情况。

否则月度统计会失真。

### 3. 加班独立记录

加班不属于基础考勤状态。

员工可以同时存在：

- 全天出勤 + 加班；
- 半天出勤 + 加班；
- 公休 + 加班。

加班时长在数据库统一以“分钟”保存，例如：

- 2 小时 30 分 = 150 分钟；
- 1 小时 45 分 = 105 分钟。

界面显示时再转换为“小时 + 分钟”。

### 4. 人员状态与月度是否参加考勤分离

人员某个月没有出勤，不等于离职。

允许：

- 7 月参加考勤；
- 8 月不参加考勤；
- 9 月重新参加考勤。

因此必须新增“月度考勤名单”概念。

人员长期状态建议为：

- 在岗；
- 暂停工作；
- 已离职。

“请假”不作为长期人员状态，而作为考勤事件。

## 五、考勤组设计

### 1. 基础考勤组

考勤组用于实际登记，不用于重复汇总。

示例：

- 特钢临时工组；
- 管业临时工组；
- 重科临时工组；
- 司机组；
- 绿化组；
- 环卫组。

每个人原则上只配置一个“默认考勤组”。

### 2. 汇总筛选不建立重复组

“全部临时工”不建立实体考勤组，而通过：

`用工类型 = 临时工`

进行动态筛选。

避免人员同时存在多个考勤组造成重复统计。

### 3. 考勤组字段

- 组 ID；
- 组名称；
- 组类型；
- 是否启用；
- 排序；
- 备注。

## 六、月度考勤名单

新增数据表：`monthly_attendance_rosters`。

其作用是确定：

> 某个月、某个考勤组，哪些人员进入本月考勤表。

支持：

- 从上月复制；
- 手动新增；
- 手动移除；
- 批量加入某考勤组；
- 标记当月不参加考勤。

人员被移出某月考勤名单后：

- 不自动生成当月日考勤；
- 不计入未登记提醒；
- 不视为离职；
- 历史记录保留。

## 七、每日考勤

### 1. 页面结构

顶部：

- 日期选择；
- 今天；
- 前一天 / 后一天；
- 本地已保存状态。

考勤组切换：

- 特钢临时工组；
- 管业临时工组；
- 司机组等。

快捷操作：

- 一键全勤；
- 复制前一天；
- 批量公休；
- 批量停工。

人员行：

| 姓名 | 上午 | 下午 | 加班 | 备注 |
|---|---|---|---|---|

上午、下午使用下拉状态快速切换。

### 2. 自动保存

页面操作应自动保存草稿或直接保存到本地数据库。

同时提供“保存考勤”按钮用于明确确认。

### 3. 修改规则

- 同一人员同一天只有一条基础考勤记录；
- 上午和下午各保存一个状态；
- 已离职日期之后禁止登记出勤；
- 入职日期之前禁止登记；
- 不在当月考勤名单中的人员默认不进入登记列表；
- 已锁定月份修改时需要先解锁。

## 八、月考勤表

### 1. 核心展示方式

采用：

- 固定姓名列；
- 日期区域横向滑动；
- 最后固定或可见“出勤、请假”统计列；
- 最后一行显示全部人员合计。

### 2. 符号规则

建议：

- `力`：全天出勤；
- 自定义“半力图形”：半天出勤；
- `🔺`：缺勤 / 无出勤；
- `休`：公休；
- `停`：停工。

注意：半力不依赖系统字体字符，使用 Flutter 自定义绘制图标，保证安卓设备显示一致。

点击单元格后可查看并修改当天上午、下午状态。

### 3. 行末统计

每名员工最后两列：

- 出勤；
- 请假。

支持 0.5 计数。

最后一行：

- 所有人出勤合计；
- 所有人请假合计。

## 九、请假管理

请假记录独立保存，同时影响对应日期的上午/下午考勤。

### 1. 请假类型

- 事假；
- 病假；
- 其他；
- 用户自定义。

### 2. 请假时长

第一版支持：

- 全天；
- 上午；
- 下午；
- 跨多天。

按小时请假作为可扩展能力预留，不作为第一版核心入口。

### 3. 规则

- 全天请假：上午请假 + 下午请假；
- 上午请假：上午请假；
- 下午请假：下午请假；
- 跨天自动拆分；
- 跨月分别计入对应月份；
- 删除请假记录时检查是否需要恢复基础考勤状态。

## 十二、月度汇总

### 1. 每人统计

- 月初状态；
- 月末状态；
- 是否参加本月考勤；
- 实际出勤天数；
- 请假天数；
- 缺勤天数；
- 公休天数；
- 停工天数；
- 加班次数；
- 加班总分钟；
- 是否月内入职；
- 是否月内离职；
- 数据完整状态。

### 2. 计算方式

每天上午、下午分别占 0.5。

例如：

- 出勤 + 出勤 = 出勤 1；
- 出勤 + 请假 = 出勤 0.5、请假 0.5；
- 缺勤 + 缺勤 = 缺勤 1；
- 公休 + 公休 = 公休 1。

加班单独求和，不计入基础出勤天数。

### 3. 汇总状态

- 未生成；
- 待检查；
- 已确认；
- 已锁定。

锁定后修改必须先解锁并记录原因。

### 4. 异常检查

自动检查：

- 当月考勤名单人员是否存在未登记；
- 入职前考勤；
- 离职后考勤；
- 上午/下午状态异常；
- 请假记录与考勤冲突；
- 加班时间重叠；
- 月度名单与人员状态不一致；
- 已离职但未停保。

- 月考勤表强调横向数据矩阵；
- 月度汇总强调异常检查与导出。

已有 UI 设计图应作为开发视觉参考，不要求像素级完全一致，但必须保持整体风格、模块布局与交互意图一致。

## 二十、版本结论

V2 将第一阶段的核心从“普通人员档案 + 小时制考勤”调整为：

> 人员档案 + 考勤组 + 月度考勤名单 + 上午/下午半天制考勤 + 独立加班 + 月考勤表 + 月度汇总。

这套结构更贴近实际临时工和现场作业人员的管理方式，也为后续车辆、物资、采购等模块提供统一的本地数据架构基础。
