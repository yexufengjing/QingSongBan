# 维修单管理开发方案

> 基于当前车辆模块实现与 2026-09-26 模拟器故障记录。本文用于指导本轮开发；字段含义和验收项同时作为后续维护依据。

## 1. 现状与问题

- `RepairOrders` 已保存维修单编号、车辆、报修与故障时间、现象、维修安排、申报及实际金额、维修状态、三联票状态、完成时间和记录文本；`RepairCostItems` 与 `RepairParts` 保存明细。`RepairRepository` 支持创建、覆盖编辑、按车辆列出和修改维修状态。
- 车辆详情的「维修」页有维修卡片，但卡片不能点击进入详情；车辆管理首页的「维修管理」入口实际打开第一辆车的维修页，无法查看全车维修单。表单仅支持新建。
- 三联票状态已有「未开／已开／不需要」，但创建后没有直接修改入口。数据库没有「是否结算」「是否结账」字段。
- 模拟器日志先报 `TextEditingController was used after being disposed`，随后出现截图中的 `_dependents.isEmpty` 和错误 build scope。车辆油耗录入、年度汇总年份选择和车况编辑弹窗都存在 `showDialog` 结束后立即释放控制器的写法；弹窗退场动画期间子组件可能仍使用控制器。维修表单移除费用行时也在 `setState` 中立即释放控制器。应修复控制器的所属生命周期，再验证断言不再出现。

## 2. 功能方向与字段语义

维修单以一张工单为主记录，费用明细与备件、附件保持现有从属关系。保留现有维修状态（已报修、待维修、维修中、已完成、已取消），新增三个可独立修改的业务标记：

| 标记 | 数据定义 | 界面文案 | 修改规则 |
| --- | --- | --- | --- |
| 三联票据 | 现有 `ticketStatus`：`notIssued`／`issued`／`notRequired` | 未开／已开／不需要 | 可随时在详情页修改；不自动改变维修状态 |
| 结算 | 新增 `isSettled`，默认 `false`；`settledAt` 可空 | 未结算／已结算 | 确认维修金额已核对；改为已结算时记录时间，撤销时清空时间 |
| 结账 | 新增 `isPaid`，默认 `false`；`paidAt` 可空 | 未结账／已结账 | 确认款项已付；改为已结账时记录时间，撤销时清空时间 |

结算表示费用金额已核对，结账表示款项已付。两个标记保留独立性，以容纳历史补录和实际业务顺序；如出现「已结账、未结算」，界面给出核对提示，但不覆盖用户输入。改变任何标记只更新该工单与 `updatedAt`，不重写费用、备件或维修状态。旧数据库迁移后两个新标记为「否」，时间为空；现有三联票据值保持原样。

## 3. 页面和操作流程

1. `/vehicles` 的「维修管理」进入 `/vehicles/repairs`，列出全部未删除维修单。显示工单编号、车辆、故障现象、报修日期、维修状态、申报与实际金额、三个业务标记。支持关键词（编号、车牌、车辆名、故障现象、供应商）和车辆、维修状态、三联票、结算、结账筛选。空列表给出新建入口。
2. 全车列表和单车「维修」卡片点击进入 `/vehicles/repairs/:repairOrderId`。详情页展示结构化字段、费用明细合计、备件、记录文本及附件入口，并提供修改状态、三联票、结算、结账的明确操作。保存后列表和单车页立即刷新。
3. 全车列表「新建维修单」先选择车辆，再进入现有创建表单。单车页仍可直接创建。详情页「编辑」打开同一表单的编辑模式，载入现有字段和费用明细；保存时按已有 repository 事务更新。
4. 新报修单可以没有费用明细，实际金额为 0；只有用户添加费用行时才要求填写项目、数量和单价。费用合计仍由明细计算，不能手填覆盖。
5. 页面返回使用可用路由判断；直接以 `/vehicles` 启动时返回首页，避免 `GoError: There is nothing to pop`。

## 4. 实现位置

- 数据：`database_tables.dart`、`app_database.dart`（版本 18 → 19 的增量迁移）、生成的 `app_database.g.dart`；`repair_repository.dart` 提供单工单读取、全车列表与仅修改标记的方法。
- 页面：新增全车列表与详情页；扩展 `vehicle_repair_form_page.dart` 的编辑模式；接入 `app_router.dart`、`vehicle_page.dart`、`vehicle_repair_tab.dart`。将 `/vehicles/repairs` 路由放在 `/vehicles/:vehicleId` 之前，避免静态路径被车辆 ID 路由拦截。
- 崩溃：输入控制器由弹窗 `State` 持有并在弹窗组件真正销毁时释放；动态费用行也在旧行退出组件树后释放。保存回调检查 `mounted`。
- 演示数据：现有 `vehicle_demo_data_seeder.dart` 已有未开与已开票据、待维修与已完成工单，迁移后可用于检视列表和详情；不重复插入原有演示车辆。

## 5. 验收要点

- 旧数据库升级后，原维修单与费用明细完整；三联票原值不变，新结算、结账标记默认为否。新库创建也含全部字段。
- 从车辆管理首页可看到全部车辆的维修单；从单车维修卡片进入的是同一张详情。列表筛选、详情编辑和返回路径正常。
- 三个业务标记可以反复修改，退出重进后保持；仅改标记时费用明细数量与金额不变。维修状态改变时车辆状态仍按现有规则同步。
- 新建无费用的报修单可保存；已有费用明细可编辑。取消弹窗、保存弹窗、移除费用行和页面返回均不再触发控制器已释放及 Flutter 断言。
