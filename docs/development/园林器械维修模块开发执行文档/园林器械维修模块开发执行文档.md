# 园林器械维修模块开发执行文档

> 适用项目：轻松办 APP  
> 模块定位：园林器械维修后信息登记、月度台账汇总、数据分析与价格比对  
> 核心原则：**便捷录入、便捷查看、月度全貌优先、分析独立、风格统一**

---

## 1. 模块背景与业务定位

本模块不是维修流程管理系统，不负责“报修、审批、待维修、维修中、维修完成”等过程状态管理。

实际业务流程为：

1. 园林器械已经完成维修；
2. 每月从维修相关人员处获取维修票据/维修记录；
3. 票据上记录具体月份、日期、维修单位、维修人及当日维修项目；
4. 管理人员将这些已完成维修的信息统一录入 APP；
5. APP 按月形成维修台账，并自动计算每日/分组小计、月度总计；
6. 后续可独立进入数据分析、价格比对页面进行统计与辅助判断。

因此，本模块应以“**月度维修台账**”为中心，而不是以设备生命周期或维修工单流程为中心。

---

## 2. 关键业务定义

### 2.1 维修单位

“维修单位”不是外部维修商，而是**维修人员所属公司/分厂**。

当前典型值：

- 特钢
- 管业
- 重科
- 后续可扩展其他单位

维修单位属于基础数据，应支持新增、编辑、停用，但历史记录必须保留原单位名称快照，避免基础数据改名后影响历史台账。

### 2.2 维修人

“维修人”指实际执行维修的员工，不是固定人员。

示例：

- 特钢 / 张三
- 管业 / 李四
- 重科 / 王五

维修人与维修单位联动：选择“特钢”后，维修人下拉仅优先显示特钢所属人员；同时允许新增人员。

### 2.3 维修记录分组

首页展示以“**维修日期 + 维修单位 + 维修人**”为一个维修记录组。

例如：

`9月3日  特钢  张三`

其下可以有多条维修明细。

同一日期如存在不同单位或不同维修人，应形成独立分组，例如：

- 9月3日 / 特钢 / 张三
- 9月3日 / 管业 / 李四

### 2.4 维修明细

每条明细包含：

| 字段 | 必填 | 说明 |
|---|---|---|
| 项目名称 | 是 | 如割草机刀片、化油器、润滑油等 |
| 规格型号 | 否 | 如 300mm、GX35、4L、M8 |
| 计数单位 | 是 | 个、片、桶、台、套、次等 |
| 数量 | 是 | 支持整数和小数 |
| 单价 | 是 | 金额单位为元 |
| 金额 | 自动 | 数量 × 单价 |
| 备注 | 否 | 如更换、保养用、维修等 |

金额默认自动计算，不建议直接手填，以减少错误。

# 5. 页面一：月度维修台账首页

参考预览：`images/02_月度维修台账首页预览.png`

## 5.1 页面目标

用户进入模块后，无需任何二次跳转即可看到当月维修内容全貌。

首页主要回答：

- 这个月修了哪些内容？
- 哪一天修的？
- 哪个单位、哪个人负责？
- 每组多少钱？
- 当月总计多少钱？

## 5.2 页面顶部

顶部结构：

- 返回按钮
- 标题：`9月器械维修信息`
- 新增
- 分析
- 比价
- 月份选择器，例如：`2026年9月`

月份切换支持：

1. 点击年月选择；
2. 左右滑动切换上/下月（可选增强）；
3. 切换后自动刷新当月记录。

## 5.3 月度摘要

建议保留 3 个摘要卡：

- 本月合计
- 记录组数
- 项目条数

说明：

- 记录组数 = 不同“日期 + 维修单位 + 维修人”的分组数量；
- 项目条数 = 当月全部维修明细行数；
- 不在首页展示过多 KPI，避免遮挡月度台账主体。

## 5.4 分组显示结构

每个维修组由“组头 + 明细 + 小计”组成。

### 组头

只显示一次：

`9月3日 | 特钢 | 张三`

禁止在每一条明细中重复显示维修单位和维修人。

### 明细表头

固定字段：

`项目名称 | 规格 | 单位 | 数量 | 单价 | 金额 | 备注`

### 分组小计

每组末尾右对齐显示：

`小计：¥145.00`

小计计算规则：

`分组小计 = 当前组全部明细金额之和`

## 5.5 月度总计

页面底部设置明显的总计区域：

- 合计金额：`¥4,386.00`
- 金额大写：`肆仟叁佰捌拾陆元整`
- 右侧突出显示“总计”

金额大写由系统自动生成。

## 5.6 分组操作

每组右上角提供“更多”菜单：

- 编辑本组
- 复制本组
- 删除本组
- 查看附件

删除需二次确认。

## 5.7 大量数据情况下的显示

首页默认全部展开，优先满足“看清整月全貌”。

当单月数据较多时，可以增加：

- 点击组头收起/展开；
- “全部展开 / 全部收起”；
- 保持顶部月份与月度摘要可见；
- 滚动过程中不使用过大的吸顶元素。

# 6. 页面二：新增 / 编辑维修记录

参考：`images/03_新增维修记录页参考.png`

> 最终实现时必须继续套用“轻松办”最新视觉规范，现有参考图主要用于页面结构说明。

## 6.1 页面目标

尽量减少用户输入次数，让用户拿着维修票据能够快速连续录入。

## 6.2 基础信息

字段：

- 维修月份
- 维修日期
- 维修单位
- 维修人

### 交互规则

- 维修月份默认当前查看月份；
- 维修日期默认当天，可手动选择；
- 维修单位从基础数据选择；
- 维修人与维修单位联动；
- 新增下一组时可以自动继承上一次的“维修月份”，减少重复选择。

## 6.3 维修明细连续录入

用户在一个页面内连续增加多条明细，不需要每条保存一次。

每行：

- 项目名称
- 规格
- 单位
- 数量
- 单价
- 金额（只读自动计算）
- 备注
- 删除

底部：`+ 添加明细`

## 6.4 输入辅助

### 项目名称历史联想

输入项目名称时，根据历史数据提供建议，例如输入“化”出现：

- 化油器
- 化油器总成

但必须允许手动输入新项目。

### 规格与单位记忆

当用户选中历史项目时，可自动带出最近常用规格和计数单位，但仍允许修改。

### 数量与单价

- 数量允许小数；
- 单价支持 2 位小数；
- 金额实时自动更新；
- 页面下方小计实时更新。

## 6.5 保存方式

提供：

### 保存

保存当前分组并返回月度首页。

### 保存并继续

保存当前分组后清空明细，但保留维修月份；可选择保留上一组日期/单位/维修人，继续录下一组。

这是高频录入场景的重要快捷功能。

## 6.6 编辑逻辑

编辑已有分组时：

- 可修改日期、单位、维修人；
- 可新增/删除明细；
- 修改数量或单价后自动重新计算；
- 小计和月度总计同步刷新；
- 历史价格分析自动以新数据重新计算。

# 8. 页面三：数据分析

参考：`images/04_数据分析页参考.png`

数据分析必须独立页面，不挤占首页台账空间。

## 8.1 顶部筛选

提供：

- 年份：2026年
- 周期：年度 / 月度
- 维修单位：全部 / 特钢 / 管业 / 重科

筛选条件变化后，所有指标和图表同步更新。

## 8.2 核心指标卡

建议 4 个：

- 年度维修金额
- 项目总数
- 月均金额
- 维修人数

## 8.3 月度维修费用趋势

图表：折线图。

横轴：1—12月  
纵轴：维修金额（元）

交互：

- 点击数据点显示该月金额；
- 可点击某个月进入对应月度台账；
- 年份切换后刷新整条趋势。

## 8.4 维修单位费用占比

图表：环形饼图。

显示：

- 特钢金额及占比
- 管业金额及占比
- 重科金额及占比
- 其他单位（存在时）

点击某单位后，可临时筛选其他图表。

## 8.5 维修项目金额 TOP5 / TOP10

图表：横向柱状图。

按项目名称汇总：

`项目累计金额 = 历史期内该项目所有明细金额之和`

建议默认 TOP5，支持“查看更多”进入 TOP10/完整列表。

## 8.6 维修项目次数排行

与“金额排行”分开统计。

示例：

- 火花塞：18条
- 刀片：15条
- 化油器：12条

避免只看金额而忽略高频低价项目。

## 8.7 维修人数据统计

建议字段：

- 姓名
- 所属维修单位
- 项目条数
- 累计维修金额
- 占比

说明：此处仅用于台账数据统计，不定义为绩效评分。

## 8.8 分析页面空状态

若当前筛选周期无数据：

- 不显示空白坐标系；
- 显示项目统一空状态插画；
- 文案：`当前条件暂无维修数据`。

# 9. 页面四：价格比对

参考：`images/05_价格比对页参考.png`

价格比对为独立页面，不在首页逐条显示复杂涨跌信息。

## 9.1 价格匹配规则

第一阶段建议按照以下组合判定“同一种维修项目”：

`项目名称 + 规格型号 + 计数单位`

例如：

`化油器 + GX35 + 个`

只有三个字段一致时，才进入同组价格比较。

原因：仅按“化油器”匹配会把不同规格的产品混在一起，导致价格分析失真。

## 9.2 筛选条件

- 项目名称
- 规格型号
- 维修单位：全部 / 特钢 / 管业 / 重科
- 时间范围：近6个月 / 近12个月 / 自定义（第二阶段可增加）

## 9.3 核心价格指标

显示：

- 当前价格
- 上次价格
- 涨跌幅
- 平均价格
- 最低价
- 最高价
- 记录数

### 计算规则

`涨跌额 = 当前单价 - 上次单价`

`涨跌幅 = (当前单价 - 上次单价) / 上次单价 × 100%`

若没有上次记录，则显示“暂无对比”。

## 9.4 历史价格趋势

图表：折线图。

横轴：发生日期  
纵轴：单价

每个点保留：

- 日期
- 单价
- 维修单位
- 维修人

点击数据点弹出详情。

## 9.5 历史记录列表

字段：

- 日期
- 维修单位
- 维修人
- 单价

默认按日期倒序。

## 9.6 价格异常提示

第一阶段不做强制报警，只在价格比对页显示明显涨跌。

可预留设置：

- 上涨超过 10%
- 上涨超过 20%
- 自定义阈值

第二阶段再考虑“异常价格”提醒功能。

# 11. 汇总计算规则

## 11.1 单条金额

`金额 = 数量 × 单价`

统一保留 2 位小数。

## 11.2 分组小计

`小计 = 当前 group_id 下所有未删除明细 amount 之和`

## 11.3 月度总计

`月度总计 = 当前月份所有未删除维修组小计之和`

## 11.4 项目条数

统计当月未删除明细数量。

## 11.5 记录组数

统计当月未删除维修组数量。

## 11.6 金额大写

月度总计自动转换成人民币大写。

要求正确处理：

- 元
- 角
- 分
- 零值
- 整数金额

# 13. 录入校验

保存前检查：

- 维修月份不能为空；
- 维修日期不能为空；
- 维修日期必须属于选定维修月份；
- 维修单位不能为空；
- 维修人不能为空；
- 至少有一条维修明细；
- 项目名称不能为空；
- 单位不能为空；
- 数量必须 > 0；
- 单价必须 ≥ 0；
- 金额必须与数量 × 单价一致。

对于单价为 0 的记录允许保存，用于特殊情况，但建议备注原因。

# 14. 删除与历史安全

采用软删除。

删除维修组时，其明细与附件逻辑删除，不立即物理清理。

若项目已有全局“回收站/恢复”机制，则本模块统一接入现有机制，不重复开发独立回收站。

# 18. 验收标准

开发完成后至少满足以下场景：

### 场景 A：一个日期多条项目

创建：

`9月3日 / 特钢 / 张三`

录入 3 条明细，首页只显示一次“特钢、张三”，三条内容正常排列，小计正确。

### 场景 B：同一天不同人员

创建：

- 9月3日 / 特钢 / 张三
- 9月3日 / 特钢 / 李四

首页显示为两个独立组，小计分别计算。

### 场景 C：跨单位

同月包含特钢、管业、重科，月度总计正确；数据分析饼图的单位金额合计与月度/年度总金额一致。

### 场景 D：编辑价格

将某条数量或单价修改后：

- 当前行金额实时变化；
- 当前组小计变化；
- 月度总计变化；
- 数据分析变化；
- 价格比对历史结果同步变化。

### 场景 E：历史价格

同一“项目名称 + 规格型号 + 单位”存在多次记录时，可在价格比对页显示完整历史趋势；不同规格不得混算。

### 场景 F：附件

一组维修记录可上传票据、维修前/后照片；首页不展开图片，点击后可预览。

# 19. 最终产品原则

本模块开发过程中，所有功能判断均应优先遵守以下顺序：

1. **月度维修内容能不能一眼看清；**
2. **录入一整张月度维修票据是否足够快；**
3. **维修单位和维修人是否只在需要的位置出现，不重复占用空间；**
4. **金额、小计、总计是否完全自动化；**
5. **分析与价格比对是否独立，不干扰首页；**
6. **视觉是否严格遵循轻松办项目现有 UI 规范；**
7. **不增加与实际业务无关的维修流程、审批状态、工单状态。**

最终应把该模块做成一份“**可录入、可快速浏览、可统计、可比价的智能月度维修台账**”，而不是复杂的维修管理系统。
